### Security Exposure

❌ **HIGH**: Audit logs can be permanently deleted or altered.
- **Resource**: `aws_s3_bucket_versioning.logs`
- **Exposure Type**: Log tampering and deletion
- **Issue**: `mfa_delete` is Disabled and no S3 Object Lock is configured, so any principal with `s3:DeleteObject` can permanently remove or modify production audit logs.
- **Impact**: Attackers or insiders who obtain delete permissions can erase evidence of activity, which undermines incident response, forensics, and compliance attestations.

⚠️ **MEDIUM**: Audit bucket logs its own access records.
- **Resource**: `aws_s3_bucket_logging.logs`
- **Exposure Type**: Self-referencing access logging
- **Issue**: `target_bucket` equals the source bucket, so server access logs are written back into the audit bucket.
- **Impact**: Each log write generates another log record, which creates a feedback loop that inflates the audit bucket, its storage costs, and its request costs.

⚠️ **MEDIUM**: Non-TLS access to the audit bucket is not blocked.
- **Resource**: `aws_s3_bucket_policy.trail`
- **Exposure Type**: Unencrypted transport
- **Issue**: The policy has no Deny statement enforcing `aws:SecureTransport` for all principals. The existing SecureTransport check uses a `StringEquals` string comparison where a `Bool` condition is required.
- **Impact**: Requests made over plain HTTP may succeed, which exposes log data and credentials in transit.

⚠️ **MEDIUM**: CloudTrail log delivery may fail.
- **Resource**: `aws_kms_key.logs`
- **Exposure Type**: Missing key policy grant
- **Issue**: No key policy is defined, so the default policy applies. The CloudTrail service principal lacks `kms:GenerateDataKey`.
- **Impact**: Log delivery to the SSE-KMS-encrypted bucket can fail silently, creating gaps in audit coverage.

ℹ️ **LOW**: No trail-level KMS encryption.
- **Resource**: `aws_cloudtrail.main`
- **Exposure Type**: Encryption configuration
- **Issue**: `kms_key_id` is not set, so log files rely on the bucket default encryption rather than the dedicated `aws_kms_key.logs` key.
- **Impact**: Key-level access control and audit of log decryption are weaker than they could be.

### Cost Impact

- **`aws_s3_bucket_versioning.logs`**: Versioning on a production audit bucket with no lifecycle rules causes noncurrent versions to accumulate indefinitely, so storage costs grow without limit. Add lifecycle rules that transition or expire noncurrent versions according to the retention policy.
- **`aws_s3_bucket_logging.logs`**: Self-referencing logging adds PUT request charges and recursively increases stored log volume. Fixing this also removes the cost feedback loop.
- **`aws_kms_key.logs`**: The customer-managed key adds a fixed monthly charge plus per-request fees. `bucket_key_enabled = true` already reduces KMS request volume for the SSE-KMS bucket, so keep it enabled.
- **`aws_cloudtrail.main`**: The multi-region trail with management events incurs S3 storage and delivery costs that scale with account activity in every region.

## Unified Recommendations

Recommendations are ordered by severity. Only the first item has a generated remediation. The others include implementation guidance derived from the findings, which the workflow has not yet validated.

**1. ❌ HIGH: Protect audit logs from deletion and alteration** (`aws_s3_bucket_versioning.logs`, `aws_s3_bucket.logs`)
- **Immediate step:** Enable MFA Delete out of band using root credentials, because the Terraform provider cannot safely set it:
  ```bash
  aws s3api put-bucket-versioning --bucket <logs-bucket> \
    --mfa "arn:aws:iam::<acct>:mfa/root-device <code>" \
    --versioning-configuration Status=Enabled,MFADelete=Enabled
  ```
  Record this step in the runbook, since the HCL state will not reflect it.
- **Object Lock:** Set `object_lock_enabled = true` on `aws_s3_bucket.logs`. This setting can only be applied at bucket creation and forces replacement of an existing bucket, so plan a migration to a new bucket. Then add:
  ```hcl
  resource "aws_s3_bucket_object_lock_configuration" "logs" {
    bucket = aws_s3_bucket.logs.id
    rule {
      default_retention {
        mode = "COMPLIANCE"
        days = 365
      }
    }
  }
  ```
- **Guardrail:** Add `lifecycle { prevent_destroy = true }` to `aws_s3_bucket.logs`.
- **Decision required:** COMPLIANCE mode cannot be shortened or bypassed, including by root, until retention expires. Confirm the 365-day retention period with compliance and legal stakeholders before applying.

**2. ⚠️ MEDIUM: Enforce TLS on the audit bucket** (`aws_s3_bucket_policy.trail`)
- Add a Deny statement for all principals on `s3:*` when `aws:SecureTransport` is `false`, using a `Bool` condition rather than `StringEquals`.
- Replace the existing `StringEquals` SecureTransport check so it does not conflict with the new Deny statement.

**3. ⚠️ MEDIUM: Grant CloudTrail access to the KMS key** (`aws_kms_key.logs`)
- Add a key policy statement that allows the `cloudtrail.amazonaws.com` service principal to perform `kms:GenerateDataKey*` and `kms:DescribeKey`, scoped with an `aws:SourceArn` condition to `aws_cloudtrail.main`. Keep the account root administrative statement in place.

**4. ⚠️ MEDIUM: Stop self-referencing access logs**
