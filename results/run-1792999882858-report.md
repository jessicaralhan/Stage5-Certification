## Infrastructure (Terraform) Findings

**Risk Level: HIGH**

### Security Exposure

#### ❌ **HIGH**: S3 Bucket Self-Logging Configuration (Infinite Recursion Risk)
- **Resource**: `aws_s3_bucket_logging.logs`
- **Issue**: S3 bucket is configured to log access logs to itself, creating a potential infinite recursion and circular logging scenario that could rapidly fill the bucket and exhaust storage capacity.
- **Impact**: Audit logs could become unusable; storage costs could spike unexpectedly; CloudTrail and other audit mechanisms relying on this bucket may fail.
- **Why It Matters**: In production environments, audit trails are critical compliance requirements. A self-referential logging configuration undermines the purpose of audit logging and creates operational risk.

**Remediation**: Create a separate dedicated S3 bucket for logs. Modify `aws_s3_bucket_logging.logs` to point `target_bucket` to a new bucket resource (e.g., `aws_s3_bucket.log_storage`) instead of itself.

---

#### ❌ **HIGH**: Missing KMS Key Policy for CloudTrail Encryption
- **Resource**: `aws_cloudtrail.main`
- **Issue**: CloudTrail is configured to use KMS encryption but lacks an explicit KMS key policy statement granting the CloudTrail service principal (`cloudtrail.amazonaws.com`) permission to generate and decrypt data keys.
- **Impact**: CloudTrail may fail to write logs to S3 or decrypt existing logs, breaking audit logging. Security events will not be recorded.
- **Why It Matters**: Without proper KMS permissions, the audit trail is non-functional, leaving the organization unable to detect or investigate security incidents.

**Remediation**: Add the following principal permission to the KMS key policy:
```json
{
  "Effect": "Allow",
  "Principal": {
    "Service": "cloudtrail.amazonaws.com"
  },
  "Action": [
    "kms:GenerateDataKey",
    "kms:DecryptDataKey"
  ],
  "Resource": "*"
}
```

---

#### ❌ **HIGH**: MFA Delete Disabled on Versioned Audit Bucket
- **Resource**: `aws_s3_bucket_versioning.logs`
- **Issue**: Versioning is enabled on the production audit log bucket, but MFA delete is disabled (`mfa_delete = false`). This removes a critical safeguard that requires MFA authentication to permanently delete object versions.
- **Impact**: Any principal with `s3:DeleteObject` permission (including compromised credentials) can permanently erase audit logs without additional authentication. Regulatory compliance violations (SOC 2, ISO 27001, etc.) and forensic evidence loss.
- **Why It Matters**: Audit logs are often subject to retention policies and legal holds. Without MFA delete, malicious actors or accidental actions can destroy evidence of security incidents.

**Remediation**: Enable MFA delete in the versioning configuration by setting `mfa_delete = true` in `aws_s3_bucket_versioning.logs.versioning_configuration`. Note: This requires root account MFA device and delete confirmation.

---

#### ⚠️ **MEDIUM**: Overly Broad S3 Bucket Encryption Access
- **Resource**: `aws_s3_bucket_server_side_encryption_configuration.logs`
- **Issue**: S3 bucket encryption uses KMS, but the KMS key policy does not explicitly restrict which principals can decrypt logs. This allows potentially overly broad access to encrypted audit data.
- **Impact**: Any principal with KMS decrypt permissions could access sensitive information in audit logs (API calls, user actions, etc.) without explicit authorization from the bucket owner.
- **Why It Matters**: Audit logs often contain sensitive operational details; access should be restricted to a minimal set of authorized principals (e.g., security team, compliance auditors).

**Remediation**: Add resource-based restrictions to the KMS key policy and S3 bucket policy. Implement least-privilege access by explicitly listing authorized principals and using conditions (e.g., source IP, MFA requirement, principal ARN) to restrict decrypt operations.

---

### Cost Impact

- **KMS Key Management**: Creation and ongoing management of the KMS key will incur AWS KMS costs (~$1/month per key) plus per-request encryption/decryption fees (~$0.03 per 10,000 requests).
- **S3 Versioning**: Enabling versioning on the production audit bucket increases storage costs because all object versions are retained. Estimate storage cost increase based on log volume and retention period.
- **CloudTrail with KMS**: CloudTrail ingestion charges apply to all logged API calls, plus S3 storage costs for encrypted objects, plus KMS encryption costs. Budget accordingly based on API call volume.
