## Infrastructure (Terraform) Findings

### Destructive Changes

No destructive changes were detected. No resources are scheduled for deletion or forced replacement.

### Security Exposure

❌ **HIGH**: Audit log delivery may silently fail
- **Resource**: `aws_cloudtrail.main`, `aws_kms_key.logs`
- **Exposure Type**: Missing KMS authorization for service principal
- **Issue**: CloudTrail delivers to a KMS-encrypted bucket, but `aws_kms_key.logs` has no key policy granting `cloudtrail.amazonaws.com` the `kms:GenerateDataKey*` and `kms:DescribeKey` actions. Log delivery will likely fail.
- **Impact**: Audit logging is silently lost. Failed deliveries may not raise alarms unless CloudTrail delivery-failure monitoring is in place, which creates a compliance gap and removes forensic coverage.
- **Note**: The analyzer attributes the gap to the bucket policy. KMS access for a service principal is granted through the key policy (or grants), so the remediation targets `aws_kms_key.logs`. This should be confirmed against live IAM and KMS state.

❌ **HIGH**: MFA Delete disabled on the audit log bucket
- **Resource**: `aws_s3_bucket_versioning.logs`
- **Exposure Type**: Missing MFA protection on destructive S3 operations
- **Issue**: `mfa_delete` is Disabled. Any principal with `s3:DeleteObjectVersion` can permanently purge audit log versions without MFA.
- **Impact**: An attacker or insider with delete permissions could destroy audit evidence, undermining incident response and compliance attestations.

⚠️ **MEDIUM**: Trail is not encrypted with the dedicated CMK
- **Resource**: `aws_cloudtrail.main`
- **Exposure Type**: Encryption configuration gap
- **Issue**: The trail has no `kms_key_id`, so logs are not encrypted with `aws_kms_key.logs` and rely only on bucket default encryption.
- **Impact**: Key-level access control and CloudTrail key-usage auditing do not apply to log files. Separation of duties between bucket administrators and log-encryption control is weakened.

⚠️ **MEDIUM**: Self-logging loop mixes access logs with audit logs
- **Resource**: `aws_s3_bucket_logging.logs`
- **Exposure Type**: Logging configuration defect
- **Issue**: `target_bucket = aws_s3_bucket.logs.id` writes access logs into the same bucket that holds audit logs.
- **Impact**: Access-log volume obscures audit records, and each access-log write generates another write to the same bucket, creating a feedback loop. Access logs and audit logs should be stored separately.

ℹ️ **LOW**: TLS enforcement is incomplete
- **Resource**: `aws_s3_bucket_policy.trail`
- **Exposure Type**: Transport security gap
- **Issue**: The policy has no explicit `Deny` for requests where `aws:SecureTransport` is `false`. TLS is enforced only for CloudTrail's own `PutObject` statement.
- **Impact**: Non-TLS requests to the bucket from other principals are not blocked.

ℹ️ **LOW**: Key policy and deletion window
- **Resource**: `aws_kms_key.logs`
- **Exposure Type**: Key governance and recovery gap
- **Issue**: No key policy is defined, so the key depends on default root-account permissions. `deletion_window_in_days` is 10.
- **Impact**: Recovery from accidental scheduled deletion is limited to 10 days. The default policy also gives no explicit scoping of who may administer the key.

### Cost Impact

- **`aws_kms_key.logs`**: Adds a fixed monthly key fee. `bucket_key_enabled = true` reduces SSE-KMS request charges.
- **`aws_s3_bucket.logs`**: Versioning with no lifecycle rules causes storage costs to grow indefinitely as audit log versions accumulate. Retention and lifecycle rules should be defined with compliance input, because audit logs typically have mandated retention periods.
- **`aws_s3_bucket_logging.logs`**: The self-logging configuration generates additional billable S3 PUT requests against the same bucket.
- **`aws_cloudtrail.main`**: As a multi-region trail, S3 storage for log files is billed. Any additional trails or data event selectors would add charges.
