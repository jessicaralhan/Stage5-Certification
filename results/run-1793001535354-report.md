⚠️ **HIGH**: RDS cluster encryption not bound to explicit KMS key.
   - **Resource**: `aws_rds_cluster.prod`
   - **Issue**: `storage_encrypted = true` is configured, but `kms_key_id` is not specified; the cluster defaults to AWS-managed encryption rather than using the newly created customer-managed key `aws_kms_key.rds`
   - **Impact**: Encryption key lifecycle is controlled by AWS, not your organization; customer-managed key was provisioned but remains unused; compliance frameworks requiring organizational key control are not satisfied
   - **Why This Matters**: Customer-managed KMS keys provide audit trail visibility, key rotation control, and compliance alignment. Default AWS-managed keys bypass organizational key governance requirements.

⚠️ **HIGH**: New KMS key lacks rotation policy and cost justification.
   - **Resource**: `aws_kms_key.rds`
   - **Issue**: Key creation planned without `enable_key_rotation` or `rotation_period_in_days` configuration; no documented business case for new key versus reusing existing organizational keys
   - **Impact**: Static encryption keys increase breach blast radius if compromised; ongoing monthly key storage and per-request encryption charges without cost control; potential compliance violations if key rotation is a requirement (e.g., PCI-DSS, HIPAA)
   - **Why This Matters**: Encryption key rotation is a fundamental security control. Unrotated keys that persist for years create risk accumulation. Additionally, unnecessary new KMS keys duplicate costs without clear benefit.
