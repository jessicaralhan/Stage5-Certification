## Access Control (IAM) Findings

Risk Level: **CRITICAL**

The policy grants unrestricted administrative access to all actions and resources in production with no conditions, MFA, or session constraints.

### Overly Broad Permissions

❌ **CRITICAL**: Unrestricted administrative grant in the `AllowEverything` statement.
- **Principal**: Unidentified. Attached to the policy with Sid `AllowEverything`.
- **Current Scope**: `Action: "*"`, `Resource: "*"`, `Effect: "Allow"`
- **Impact**: The principal can create, modify, and delete any production resource, change IAM policies and roles, read or alter KMS keys, and modify databases and security groups. A compromise of this principal's credentials gives an attacker full control of the production account.
- **Least-Privilege Target**: Replace the statement with a `ProdAppOperations` statement limited to the actions the application requires: `s3:GetObject`, `s3:PutObject`, `s3:ListBucket`, `ec2:StartInstances`, `ec2:StopInstances`, `ec2:RebootInstances`, `logs:CreateLogStream`, `logs:PutLogEvents`, and `cloudwatch:GetMetricData`. Add a `ReadOnlyDescribe` statement for `ec2:DescribeInstances` and `ec2:DescribeTags`.
- **Reviewer Note on Fix 1**: The proposed `ProdAppOperations` statement still includes `"*"` in its Resource array. This negates the resource scoping for every listed action and must be removed before deployment.

### Missing Resource Boundaries

❌ **CRITICAL**: Unscoped `Resource: "*"` in the `AllowEverything` statement.
- **Affected Resources**: Databases, KMS keys, security groups, and IAM resources in account `123456789012`, region `us-east-1`
- **Impact**: No ARN boundaries prevent access to sensitive resource classes. Without boundaries, scoping by action alone is insufficient.
- **Recommendation**: Scope the operational statement to the following ARNs:
  - `arn:aws:s3:::prod-app-data` and `arn:aws:s3:::prod-app-data/*`
  - `arn:aws:ec2:us-east-1:123456789012:instance/i-0abc123def4567890`
  - `arn:aws:logs:us-east-1:123456789012:log-group:/prod/app:*`
- **Note on Fix 2**: The proposed `DenyOutOfScope` statement uses `NotAction` and `NotResource` to block out-of-scope access. Fix 1 instead uses `instance/*` as the EC2 ARN, which conflicts with the single-instance ARN in Fix 2. The two fixes must be reconciled to a single instance ARN, or the scope must be widened deliberately with documented justification.
- **Describe Calls**: `ec2:Describe*` requires `Resource: "*"` in AWS. This is an accepted exception and should be documented as such.

### Missing MFA/Conditions

❌ **CRITICAL**: No MFA requirement for destructive or privilege-changing actions.
- **Principal**: Unidentified
- **Gap**: Create, delete, modify, and IAM-change actions are permitted without `aws:MultiFactorAuthPresent`.
- **Proposed Remediation**: Add `Bool: {"aws:MultiFactorAuthPresent": "true"}` and `NumericLessThan: {"aws:MultiFactorAuthAge": "3600"}` to the operational statement. Add a `DenyWithoutMFA` statement using `BoolIfExists` on `aws:MultiFactorAuthPresent` set to `false`.
- **Reviewer Concern**: The `DenyWithoutMFA` statement applies to `Action: "*"` and `Resource: "*"`. It will break MFA-less automation and service roles. It must be scoped with exceptions for documented automation principals, or those principals must be moved to a separate policy.

⚠️ **HIGH**: No Condition block restricting access by context.
- **Principal**: Unidentified
- **Gap**: No source IP, `aws:SourceVpc`, time window, or request tag restrictions.
- **Impact**: Credentials for this principal are usable from any network location at any time.
- **Recommendation**: Add `aws:SourceVpc` or `aws:SourceIp` conditions matching the production VPC and approved CIDR ranges. This is not addressed by the current proposed fixes.

- **Impact**: A stolen session token remains usable for up to 12 hours with full administrative access.
- **Recommendation**: Set `MaxSessionDuration` on the associated role to 3600 seconds (1 hour), the minimum allowed value. Confirm that the 1-hour setting does not break long-running automation.
