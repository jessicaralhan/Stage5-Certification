### Security Exposure

❌ **HIGH**: Audit bucket logs into itself
- **Resource**: `aws_s3_bucket_logging.logs`
- **Exposure type**: Self-referential access logging (`target_bucket` equals the source bucket)
- **Impact**: Creates a write feedback loop that can generate unbounded log objects and undermines audit integrity, because the log destination is also the source being audited.

❌ **HIGH**: CloudTrail cannot write to the encrypted log bucket
- **Resource**: `aws_kms_key.logs`
- **Exposure type**: Missing key policy grants for `cloudtrail.amazonaws.com` (`kms:GenerateDataKey`, `kms:Decrypt`)
- **Impact**: CloudTrail delivery to the SSE-KMS bucket will likely fail, leaving audit logging effectively disabled.

⚠️ **MEDIUM**: MFA Delete disabled on audit-log bucket
- **Resource**: `aws_s3_bucket_versioning.logs`
- **Exposure type**: Deletion protection gap
- **Impact**: Any principal with `s3:DeleteObjectVersion` can permanently remove log versions, including evidence of their own activity.

⚠️ **MEDIUM**: Non-TLS access not denied
- **Resource**: `aws_s3_bucket_policy.trail`
- **Exposure type**: No explicit Deny for `aws:SecureTransport = false`
- **Impact**: Requests over unencrypted HTTP are not blocked for all principals.

⚠️ **MEDIUM**: No Object Lock on audit bucket
- **Resource**: `aws_s3_bucket.logs`
- **Exposure type**: Missing S3 Object Lock configuration
- **Impact**: Log objects can be overwritten or deleted before retention requirements are met.

### Cost Impact

- **`aws_s3_bucket_logging.logs`**: The self-referential logging loop will generate log objects continuously, so storage and request costs will grow over time. Resolving the HIGH finding above also resolves this cost issue.
- **`aws_s3_bucket_versioning.logs`**: Versioning without a noncurrent-version lifecycle rule will steadily increase S3 storage costs.
- **`aws_kms_key.logs`**: `bucket_key_enabled` reduces KMS request charges, but CloudTrail and S3 writes still incur ongoing KMS API costs. Monitor these as log volume grows.

## Unified Recommendations

### HIGH

1. **Stop self-referential access logging on `aws_s3_bucket_logging.logs`.**
   - Point `target_bucket` to a separate, dedicated access-log bucket, for example `<org>-s3-access-logs`, that is not the audit bucket.
   - Give the access-log bucket its own encryption and a lifecycle expiration rule so that it does not grow without limit.

2. **Add a CloudTrail statement to the key policy on `aws_kms_key.logs`.**
   - Grant the `cloudtrail.amazonaws.com` service principal `kms:GenerateDataKey*` and `kms:DescribeKey`, and `kms:Decrypt` for log file validation.
   - Scope the statement with conditions: `kms:EncryptionContext:aws:cloudtrail:arn` matching the trail ARN, and `aws:SourceArn` matching the trail ARN.
   - Verify delivery after apply by checking the trail's latest delivery status and confirming that new log objects appear in the bucket.

### MEDIUM

3. **Enable MFA Delete on `aws_s3_bucket_versioning.logs`.**
   - MFA Delete can only be enabled by the root account using its MFA device. It cannot be set through a standard Terraform apply, so schedule this as a manual step and record it in the change ticket.
   - Restrict `s3:DeleteObjectVersion` to a break-glass role as an additional control.

4. **Deny non-TLS requests in `aws_s3_bucket_policy.trail`.**
   - Add a statement with `Effect: Deny`, `Principal: "*"`, `Action: "s3:*"`, on both the bucket and `/*` ARNs, with condition `Bool: { "aws:SecureTransport": "false" }`.
   - Confirm that CloudTrail delivery still works after the change, since the trail writes over HTTPS.

5. **Add S3 Object Lock to `aws_s3_bucket.logs`.**
   - Object Lock must be enabled at bucket creation (`object_lock_enabled = true`). Adding it to an existing bucket typically requires replacement, which is a destructive change. Plan a new bucket, migrate logs, and cut over, rather than modifying the existing bucket in place.
   - Set a default retention rule that matches your compliance requirement, for example COMPLIANCE mode with the required number of days.

### LOW

6. **Add a noncurrent-version lifecycle rule to `aws_s3_bucket_versioning.logs`.**
   - Expire noncurrent versions after the retention period required by policy, so that versioning does not increase storage costs indefinitely.
