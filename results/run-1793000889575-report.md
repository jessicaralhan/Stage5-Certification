## Infrastructure (Terraform) Findings

**Risk Level: HIGH**

### Credential & Secret Management

❌ **HIGH**: Master password lacks rotation policy and complexity enforcement.
   - **Resource:** `aws_rds_cluster.prod`
   - **Issue:** Database master password is passed as a plain Terraform variable without automated rotation or minimum complexity requirements.
   - **Impact:** Compromised credentials cannot be automatically cycled; password complexity is not enforced at deployment time, increasing brute-force risk.
   - **Recommendation:** Integrate AWS Secrets Manager with automatic rotation. Replace the variable reference with `master_password = aws_secretsmanager_secret_version.prod.secret_string`. Configure rotation rules with `rotate_immediately = true` and `AutomaticallyAfterDays = 30`.

### Key Management & Disaster Recovery

❌ **HIGH**: KMS key deletion window is dangerously short.
   - **Resource:** `aws_kms_key.rds`
   - **Issue:** KMS key is configured with a 7-day deletion window. Accidental key deletion would render all encrypted RDS data unrecoverable within one week.
   - **Impact:** Production data loss; inability to decrypt backups; compliance violation; service outage.
   - **Recommendation:** Increase `deletion_window_in_days` to 30 (or higher for production). This extends the recovery window and adds administrative safeguards against accidental destruction.

### Network Isolation

⚠ **MEDIUM**: Public accessibility attribute not explicitly configured.
   - **Resource:** `aws_rds_cluster.prod`
   - **Issue:** The `publicly_accessible` attribute is not set; default behavior may expose the cluster to unintended network access depending on security group rules.
   - **Impact:** Risk of accidental internet exposure if security group configuration is misconfigured or overly permissive.
   - **Recommendation:** Add explicit attribute `publicly_accessible = false` to the `aws_rds_cluster.prod` resource definition.

### Backup Encryption

⚠ **MEDIUM**: Backup encryption is not explicitly enforced.
   - **Resource:** `aws_rds_cluster.prod`
   - **Issue:** No `backup_encryption` attribute is specified. Although the cluster uses KMS encryption, backups may not inherit the same encryption settings.
   - **Impact:** Backup data could be stored unencrypted or with weaker encryption, violating data protection policies.
   - **Recommendation:** Explicitly set backup encryption by configuring the `backup_encryption` attribute to reference the KMS key: `backup_encryption = aws_kms_key.rds.arn`.

### Cost Impact

**No unexpected cost drivers identified.** Aurora MySQL cluster with 30-day backup retention and KMS encryption will incur standard RDS cluster charges, backup storage fees, and KMS API call costs within expected ranges.
