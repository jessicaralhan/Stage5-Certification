## Access Control (IAM) Findings

**Risk Level: CRITICAL**

Production IAM policy grants unrestricted wildcard permissions on all actions and resources without any guardrails, representing a critical security violation of least-privilege principles.

### Overly Broad Permissions

❌ **CRITICAL**: Wildcard administrative access on all AWS services
   - **Affected Principal(s)**: Unknown principal(s) bound to this policy
   - **Current Scope**: All actions (`*`) on all resources (`*`)
   - **Severity**: CRITICAL
   - **Impact**: Any entity using this policy can perform any action in the entire AWS account, including:
     - Create, modify, or delete IAM roles and policies
     - Access or delete sensitive data in S3, RDS, DynamoDB
     - Terminate running infrastructure
     - Exfiltrate encryption keys (KMS)
     - Modify security groups and network ACLs
   - **Least-Privilege Target**: Replace with service-specific, resource-scoped policies that grant only required actions (e.g., `s3:GetObject`, `s3:PutObject` on specific bucket ARNs)

### Missing Resource Boundaries

❌ **CRITICAL**: No resource scoping constraints
   - **Affected Policy**: Wildcard policy (all resources)
   - **Unscoped Resources**: All AWS resources across all services
   - **Severity**: CRITICAL
   - **Impact**: Policy permits unrestricted access to:
     - IAM (user creation, key rotation, policy attachment)
     - KMS (key creation, deletion, key material exposure)
     - RDS (database termination, backup deletion, encryption modification)
     - S3 (bucket deletion, public access configuration, object deletion)
     - EC2 security groups (inbound/outbound rule modification)
     - Secrets Manager (secret retrieval and deletion)
   - **Why This Matters**: Without resource boundaries, a compromised credential or misconfigured service has account-wide blast radius
   - **Recommendation**: Replace with resource ARN restrictions. Example:
     ```
     "Resource": [
       "arn:aws:s3:::production-data/*",
       "arn:aws:rds:us-east-1:ACCOUNT_ID:db/production-db"
     ]
     ```

### Missing MFA/Conditions

❌ **CRITICAL**: No MFA requirement for destructive operations
   - **Affected Principal(s)**: Unknown principal(s) bound to this policy
   - **Gap**: Policy lacks `aws:MultiFactorAuthPresent` condition and session duration constraints
   - **Severity**: CRITICAL
   - **Impact**: Destructive actions (delete, terminate, modify) can be executed without MFA:
     - `ec2:TerminateInstances` — production infrastructure shutdown
     - `rds:DeleteDBInstance` — database loss without confirmation
     - `s3:DeleteObject` — data deletion without second factor
     - `iam:DeleteRole` — identity infrastructure compromise
   - **Why This Matters**: Compromised programmatic credentials (API keys, temporary tokens) can cause immediate, irreversible damage
   - **Recommendation**: Implement conditional access requiring MFA for destructive operations:
     ```json
     "Condition": {
       "Bool": {
         "aws:MultiFactorAuthPresent": "true"
       }
     }
     ```
     AND restrict `DeleteDB*`, `Terminate*`, `Delete*` actions with this condition

❌ **CRITICAL**: No contextual access conditions
   - **Affected Principal(s)**: Unknown principal(s) bound to this policy
   - **Gap**: Policy contains no condition keys restricting:
     - IP address/CIDR blocks
     - Source VPC or VPC endpoint
     - Time-based access windows
     - Principal tags or role session name
   - **Severity**: CRITICAL
   - **Impact**: Unrestricted access from any network, at any time, from any context enables:
     - Lateral movement from compromised external systems
     - Credential theft without geographical anomaly detection
     - After-hours unauthorized access
   - **Why This Matters**: Defense-in-depth requires multiple layers; this policy eliminates all contextual restrictions
   - **Recommendation**: Add condition keys for production policies:
     ```json
     "Condition": {
       "IpAddress": {
         "aws:SourceIp": ["10.0.0.0/8", "203.0.113.0/24"]
       },
       "StringEquals": {
         "aws:RequestedRegion": "us-east-1"
       },
       "DateGreaterThan": {
         "aws:CurrentTime": "2026-01-01T00:00:00Z"
       },
       "DateLessThan": {
         "aws:CurrentTime": "2026-12-31T23:59:59Z"
       }
     }
     ```

2. **Replace wildcard policy with least-privilege scoped policies**
   - For each principal, analyze its actual use case (e.g., CI/CD pipeline, Lambda execution, human developer)
   - Create service-specific policies granting only required permissions
   - Example for S3-only workload:
     ```json
     {
       "Version": "2012-10-17",
       "Statement": [
         {
           "Effect": "Allow",
           "Action": [
             "s3:GetObject",
             "s3:PutObject",
             "s3:DeleteObject"
           ],
           "Resource": "arn:aws:s3:::production-data/*"
         }
       ]
     }
     ```
   - Example for Lambda execution role:
     ```json
     {
       "Version": "2012-10-17",
       "Statement": [
         {
           "Effect": "Allow",
           "Action": "logs:CreateLogGroup",
           "Resource": "arn:aws:logs:us-east-1:ACCOUNT_ID:log-group:/aws/lambda/myfunction*"
         }
       ]
     }
     ```

3. **Enforce MFA for all human principals with destructive permissions**
   - Require `aws:MultiFactorAuthPresent: "true"` condition on all policies permitting:
     - `ec2:TerminateInstances`
     - `rds:DeleteDBInstance`
     - `s3:DeleteObject`
     - `iam:*` (any IAM action)
     - `kms:ScheduleKeyDeletion`
   - Document MFA enforcement in access control policy document
   - **Action**: Update all human-used policies within 24 hours

4. **Add contextual condition keys to all policies**
   - Restrict by source IP (corporate VPN, office CIDR blocks)
   - Restrict by source VPC or VPC endpoint for AWS service access
   - Restrict by time-based windows (business hours for human access)
   - Restrict by AWS region (if not needed globally)
   - **Action**: Apply within 48 hours; coordinate with DevOps/SRE for service principal policies
