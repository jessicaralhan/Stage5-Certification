## Infrastructure (Terraform) Findings

No destructive changes were detected in the plan. No resources are scheduled for deletion or forced replacement.

### Security Exposure

❌ **HIGH**: CloudTrail cannot encrypt log writes with the logs KMS key.
- **Resource**: `aws_kms_key.logs`
- **Exposure type**: Missing service grant in key policy
- **Issue**: No key policy statement grants `cloudtrail.amazonaws.com` the `kms:GenerateDataKey` permission. CloudTrail writes to the SSE-KMS bucket will likely be denied.
- **Impact**: Audit logging can fail silently. Gaps in the audit trail may go undetected, which weakens incident investigation and compliance evidence.
- **Recommendation**: Add the `AllowCloudTrailEncrypt` statement from the Remediation section below.

❌ **HIGH**: MFA Delete is disabled on the production audit-log bucket.
- **Resource**: `aws_s3_bucket_versioning.logs`
- **Exposure type**: Missing MFA protection on destructive versioning operations
- **Issue**: MFA Delete is disabled, so compromised credentials could permanently delete log object versions.
- **Impact**: An attacker or insider with stolen credentials could destroy audit evidence and cover tracks.
- **Recommendation**: Enable MFA Delete out of band using root credentials, as described in the Remediation section below.

⚠️ **MEDIUM**: No Object Lock retention is configured on the audit-log bucket.
- **Resource**: `aws_s3_bucket.logs`
- **Exposure type**: Missing write-once retention
- **Issue**: Audit logs can be overwritten or deleted before their retention period ends.
- **Impact**: Logs may be altered or removed before retention requirements are met.
- **Recommendation**: Enabling Object Lock requires a new bucket with `object_lock_enabled = true`. This is a bucket replacement and requires a migration plan (see ESCALATE items below).

⚠️ **MEDIUM**: The bucket policy does not explicitly deny insecure transport.
- **Resource**: `aws_s3_bucket_policy.trail`
- **Exposure type**: TLS enforced only by Allow condition
- **Issue**: There is no explicit `Deny` for requests where `aws:SecureTransport` is `false`.
- **Impact**: Non-TLS requests are not explicitly blocked, leaving the control dependent on Allow logic alone.
- **Recommendation**: Add an explicit `Deny` statement with `Condition = { Bool = { "aws:SecureTransport" = "false" } }`.

⚠️ **MEDIUM**: Server access logging writes into the bucket it logs.
- **Resource**: `aws_s3_bucket_logging.logs`
- **Exposure type**: Self-referential logging
- **Issue**: The logging target is the same bucket being logged, which can create recursive log writes.
- **Impact**: Recursive writes inflate storage and request volume and can obscure audit data.
- **Recommendation**: Direct server access logs to a separate bucket dedicated to access logs.

ℹ️ **LOW**: The trail does not specify a customer-managed KMS key.
- **Resource**: `aws_cloudtrail.main`
- **Exposure type**: Implicit encryption configuration
- **Issue**: `kms_key_id` is not set, so encryption depends on the bucket default rather than the intended CMK.
- **Impact**: The encryption key in use may not match the organization's key governance intent.
- **Recommendation**: Set `kms_key_id = aws_kms_key.logs.arn` on `aws_cloudtrail.main`.

ℹ️ **LOW**: The `AWSCloudTrailWrite` statement lacks confused-deputy and boolean-type protections.
- **Resource**: `aws_s3_bucket_policy.trail`
- **Exposure type**: Weak condition scoping
- **Issue**: The statement lacks an `aws:SourceArn` condition. The `aws:SecureTransport` check compares a boolean as a string.
- **Impact**: The confused-deputy protection is weakened, and the TLS check may not evaluate as intended.
- **Recommendation**: Add `aws:SourceArn` scoped to the trail ARN. Use a boolean comparison, `Bool = { "aws:SecureTransport" = "false" }`, instead of a string comparison.

### Cost Impact

- **New KMS key** (`aws_kms_key.logs`): Adds a fixed monthly charge of approximately $1, plus per-request SSE-KMS charges. `bucket_key_enabled = true` partly offsets the request cost.
- **Bucket versioning** (`aws_s3_bucket_versioning.logs`): Noncurrent versions will accumulate and increase storage costs over time. A lifecycle rule for noncurrent versions is needed to control growth.
- **Self-targeted access logging** (`aws_s3_bucket_logging.logs`): Generates continuous PUT and storage charges that grow with request volume. Redirecting logs to a separate bucket removes the recursive cost.

### Remediation

**1. `aws_kms_key.logs`: Add CloudTrail encryption grant (HIGH, config_change)**

Add this statement to the key policy:

```hcl
{
  Sid       = "AllowCloudTrailEncrypt"
  Effect    = "Allow"
  Principal = { Service = "cloudtrail.amazonaws.com" }
  Action    = ["kms:GenerateDataKey*", "kms:DescribeKey"]
  Resource  = "*"
  Condition = {
    StringEquals = {
      "aws:SourceAccount" = data.aws_caller_identity.current.account_id
    }
    StringLike = {
      "aws:SourceArn" = "arn:aws:cloudtrail:${var.region}:${data.aws_caller_identity.current.account_id}:trail/${var.trail_name}"
    }
  }
}
```

Use `var.trail_name` rather than `aws_cloudtrail.main.name` to avoid a dependency cycle.

**2. `aws_s3_bucket_versioning.logs`: Enable MFA Delete out of band (HIGH, process_change)**

MFA Delete requires root credentials and cannot be applied by a normal IAM role. Run this once, outside Terraform:

```bash
aws s3api put-bucket-versioning \
  --bucket <bucket> \
  --versioning-configuration Status=Enabled,MFADelete=Enabled \
  --mfa "<root-mfa-serial> <code>"
```

Then keep the HCL in sync and prevent Terraform from attempting the MFA-gated change:

```hcl
resource "aws_s3_bucket_versioning" "logs" {
  bucket = aws_s3_bucket.logs.id
  versioning_configuration {
    status = "Enabled"
  }
  lifecycle {
    ignore_changes = [versioning_configuration[0].mfa_delete]
  }
}
```
