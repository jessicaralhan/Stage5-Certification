## Access Control (IAM) Findings

**Risk Level**: 🔴 **CRITICAL**

Production IAM policy grants root-equivalent permissions with no constraints, conditions, MFA requirements, or resource boundaries, representing a critical security configuration error.

### Overly Broad Permissions

❌ **CRITICAL**: Principal `AllowEverything` granted unrestricted administrative access.
- **Current Scope**: All actions (`*`) on all resources (`*`)
- **Affected Services**: EC2, S3, RDS, IAM, KMS, CloudTrail, and all other AWS services
- **Impact**: Any entity with this policy can create, modify, delete, or exfiltrate any resource in the account without audit trail filtering or accountability
- **Least-Privilege Target**: Role should be restricted to only required actions (e.g., `ec2:DescribeInstances`, `ec2:DescribeSecurityGroups`, `s3:GetObject`, `s3:PutObject`, `logs:CreateLogGroup`, `logs:CreateLogStream`, `logs:PutLogEvents`, `cloudwatch:PutMetricAlarm`, `sts:AssumeRole`)

### Missing Resource Boundaries

❌ **CRITICAL**: Policy contains no resource constraints; principals can perform any action against any AWS resource.
- **Affected Resources**: All AWS resources across all services (`*`)
- **Services at Risk**: Sensitive services including IAM (role/user management), KMS (encryption keys), RDS (databases), S3 (data storage), and CloudTrail (audit logs)
- **Impact**: No resource-level access control; malicious actors or compromised credentials can target the highest-value assets without restriction
- **Required Fix**: Scope permissions to specific resource ARNs (e.g., `arn:aws:s3:::production-app-bucket/*`, `arn:aws:ec2:us-east-1:ACCOUNT-ID:instance/i-*`)

### Missing MFA/Conditions

❌ **CRITICAL**: Policy lacks MFA requirement; allows unrestricted destructive actions without multi-factor authentication.
- **Principal**: `AllowEverything`
- **Gap**: No `aws:MultiFactorAuthPresent` condition; destructive actions (delete, terminate, modify) can be executed by any authenticated session
- **Impact**: Compromised programmatic credentials, stolen temporary tokens, or insider threats can perform irreversible infrastructure damage without a second authentication factor
- **Additional Missing Conditions**:
  - No IP restrictions (`aws:SourceIp`)
  - No source account validation (`aws:SourceAccount`)
  - No time-based access controls
  - No region restrictions in production environment

### Privilege Escalation Risks

❌ **CRITICAL**: Unrestricted IAM permissions enable privilege escalation without safeguards.
- **Risk Path**: Any principal with this policy can assume higher-privileged roles via `sts:AssumeRole` without MFA, modify IAM policies to grant themselves additional permissions, or create new roles with administrative access
- **Severity**: CRITICAL
- **Mitigation**: 
  - Restrict `sts:AssumeRole` to specific role ARNs (not wildcard)
  - Enforce MFA on `iam:*` and `sts:AssumeRole` actions
  - Implement an explicit deny policy for sensitive operations (e.g., `iam:DeleteRole`, `iam:PutUserPolicy`) unless MFA is present and request originates from trusted IP ranges

   - **Verification**: Confirm via IAM policy simulator that the overly broad statement is no longer active
   - **Timing**: Execute before any deployment to production or halt existing policy if already in effect

2. **Replace with Least-Privilege Policy Set**
   - **Action**: Implement one of the three remediation paths provided by the IAM generator, with the following requirements:
     - All statements must specify explicit actions (no wildcards in Action field)
     - All statements must specify explicit resource ARNs (no wildcards in Resource field)
     - All destructive actions (delete, terminate, modify) must require `aws:MultiFactorAuthPresent: "true"` condition
     - All statements must include IP restrictions via `aws:SourceIp` for production environment (e.g., `10.0.0.0/8` for internal access only)
     - All statements must include region restrictions via `aws:RequestedRegion` (e.g., `us-east-1` only)

3. **Implement Scoped Permissions by Service**
   - **EC2 Operations**: Restrict to `ec2:DescribeInstances`, `ec2:StartInstances`, `ec2:StopInstances` on `arn:aws:ec2:us-east-1:ACCOUNT-ID:instance/i-*` only; add MFA+IP+region conditions
   - **S3 Operations**: Restrict to `s3:GetObject`, `s3:PutObject` on `arn:aws:s3:::production-app-bucket/*` only; add MFA+IP+region conditions for destructive operations
   - **RDS Operations**: Restrict destructive actions (`rds:DeleteDBInstance`, `rds:ModifyDBInstance`) to `arn:aws:rds:us-east-1:ACCOUNT-ID:db:prod-*` only; require MFA+IP+region conditions
   - **IAM Operations**: Severely restrict (`iam:PassRole`, `sts:AssumeRole` only) to specific service role ARNs; require MFA for all operations

4. **Enforce MFA on Destructive Actions**
   - **Action**: Add explicit condition `{"Bool": {"aws:MultiFactorAuthPresent": "true"}}` to all statements permitting:
     - `ec2:TerminateInstances`
     - `rds:DeleteDBInstance`
     - `s3:DeleteObject`
     - `iam:DeleteRole`, `iam:DeletePolicy`, `iam:PutUserPolicy`
     - Any action prefixed `delete`, `terminate`, or `drop`
   - **Rationale**: Ensures at least two authentication factors are required before infrastructure can be irreversibly deleted

5. **Add Network and Account-Level Conditions**
   - **IP Restriction**: Add `"IpAddress": {"aws:SourceIp": ["10.0.0.0/8"]}` to limit access to corporate or trusted VPC ranges; adjust CIDR blocks as needed
   - **Region Restriction**: Add `"StringEquals": {"aws:RequestedRegion": "us-east-1"}` to prevent cross-region resource creation/deletion
   - **Account Validation**: Add `"StringEquals": {"aws:SourceAccount": "ACCOUNT-ID"}` to prevent cross-account assume role attacks
