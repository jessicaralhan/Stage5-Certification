# Infrastructure Security Review Report

## Executive Summary

This report covers the Terraform Safety Review of the audit logging infrastructure, which includes the CloudTrail trail `aws_cloudtrail.main`, the audit bucket and its configuration (`aws_s3_bucket_policy.trail`, `aws_s3_bucket_versioning.logs`, `aws_s3_bucket_logging.logs`), and the customer-managed KMS key `aws_kms_key.logs`. The review found no destructive changes but identified one HIGH-severity defect that would prevent CloudTrail from delivering audit logs, along with four lower-severity hardening gaps. The combined risk level is **HIGH**, and the Terraform workflow verdict is **REVISE**. The priority action is to add a CloudTrail service statement to the `aws_kms_key.logs` key policy before any apply. Remediations for the remaining findings still need to be generated and reviewed.

---

## Infrastructure (Terraform) Findings

Risk Level: **HIGH**

### Destructive Changes

No destructive changes were identified in the reviewed plan.

### Security Exposure

❌ **HIGH**: CloudTrail cannot write to the encrypted audit bucket.
- **Resource**: `aws_kms_key.logs`
- **Exposure type**: Missing key policy grant for the `cloudtrail.amazonaws.com` service principal (`kms:GenerateDataKey*`)
- **Impact**: CloudTrail writes to the SSE-KMS bucket will likely fail, so audit logging will not be delivered. This is an availability failure of the control itself. Logging gaps also weaken incident investigation and compliance evidence.

⚠️ **MEDIUM**: Non-TLS access to the audit bucket is not denied.
- **Resource**: `aws_s3_bucket_policy.trail`
- **Exposure type**: No explicit `Deny` for requests where `aws:SecureTransport` is `false`
- **Impact**: Plaintext HTTP requests to the audit bucket are not blocked, which exposes audit data in transit and violates common baseline controls.

⚠️ **MEDIUM**: Audit objects can be permanently deleted without MFA.
- **Resource**: `aws_s3_bucket_versioning.logs`
- **Exposure type**: MFA Delete is disabled
- **Impact**: Anyone with sufficient S3 permissions can permanently delete object versions, which undermines log integrity and the tamper-evidence of the audit trail.

⚠️ **MEDIUM**: The audit bucket logs its own access, creating a self-referential loop.
- **Resource**: `aws_s3_bucket_logging.logs`
- **Exposure type**: Access logs target the same bucket they monitor
- **Impact**: Each access-log write generates further log objects in the same bucket. This can obscure the audit trail with noise and makes the logging chain difficult to reason about during forensics.

ℹ️ **LOW**: CloudTrail does not use a trail-level KMS key.
- **Resource**: `aws_cloudtrail.main`
- **Exposure type**: No `kms_key_id` configured
- **Impact**: Log files rely only on bucket default encryption and not on the dedicated `aws_kms_key.logs` key. This reduces key-level control and audit visibility over log decryption.

### Cost Impact

- **`aws_s3_bucket_versioning.logs` / audit bucket**: Versioning is enabled with no lifecycle configuration, so CloudTrail and self-logged access log storage will grow without bound.
- **`aws_s3_bucket_logging.logs`**: The self-targeted access logging adds S3 request and storage charges for every access event.
- **`aws_kms_key.logs`**: The customer-managed key incurs a monthly key fee plus per-request charges. These are partly offset by `bucket_key_enabled = true`.
- **`aws_cloudtrail.main`**: The multi-region trail adds S3 storage and PUT request costs across all regions for management events.

### Verdict: REVISE

The workflow verdict is REVISE. The adversarial reviewer returned REVISE because the remediation placeholder was not populated for all findings. A remediation was generated only for `aws_kms_key.logs`. The reviewer's stated reasoning does not match the remediation output that was recorded, so the review record should be corrected. Remediations are still required for `aws_s3_bucket_policy.trail`, `aws_s3_bucket_versioning.logs`, `aws_s3_bucket_logging.logs`, `aws_s3_bucket_lifecycle_configuration` (to be created for the audit bucket), and `aws_cloudtrail.main` before the plan can be approved.

## Unified Recommendations

### HIGH

1. **Add a CloudTrail service statement to `aws_kms_key.logs`.** Retain the existing root statement and add the following statement. Replace the `<account_id>` placeholder with the interpolated value `${data.aws_caller_identity.current.account_id}` in the Terraform HCL.
   ```hcl
   {
     Sid       = "AllowCloudTrailEncrypt"
     Effect    = "Allow"
     Principal = { Service = "cloudtrail.amazonaws.com" }
     Action    = ["kms:GenerateDataKey*", "kms:DescribeKey"]
     Resource  = "*"
     Condition = {
       StringEquals = { "aws:SourceAccount" = data.aws_caller_identity.current.account_id }
       StringLike   = { "kms:EncryptionContext:aws:cloudtrail:arn" = "arn:aws:cloudtrail:*:${data.aws_caller_identity.current.account_id}:trail/*" }
     }
   }
   ```
   - **Validation**: Run `terraform plan`, then confirm with a test CloudTrail delivery that new log objects appear in the audit bucket and that no `AccessDenied` errors are recorded in CloudTrail's delivery status.
   - **Ordering**: Apply this change before any change that depends on CloudTrail writing to the bucket.

### MEDIUM

2. **Deny non-TLS access in `aws_s3_bucket_policy.trail`.** Add a statement with `Effect = "Deny"`, `Principal = "*"`, `Action = "s3:*"`, applied to both the bucket ARN and `/*`, with `Condition = { Bool = { "aws:SecureTransport" = "false" } }`.

3. **Enable MFA Delete on the audit bucket.** Set `mfa_delete = "Enabled"` in `aws_s3_bucket_versioning.logs`. AWS allows this change only when called with root account credentials and an MFA device, so it cannot be applied through a standard CI role. Plan a one-time manual step and document it.

4. **Remove the self-referential logging loop.** Create a separate, dedicated log-destination bucket for S3 server access logs and point `aws_s3_bucket_logging.logs` at it. Do not allow the audit bucket to write its access logs to itself.

5. **Add a lifecycle policy for the audit bucket.** Create an `aws_s3_bucket_lifecycle_configuration` for the audit bucket. Transition noncurrent versions and objects to lower-cost storage classes, and set an expiration that matches your retention requirements. Without this, storage costs will grow without bound.

### LOW

6. **Set a trail-level KMS key on CloudTrail.** Set `kms_key_id = aws_kms_key.logs.arn` on `aws_cloudtrail.main`. Apply this only after the key policy fix in recommendation 1 is in place. Otherwise, CloudTrail delivery will fail.
