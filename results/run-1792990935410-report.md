## Unified Recommendations

### CRITICAL

1. **Eliminate the forced replacement of `aws_rds_cluster.prod`.**
   - Set `db_subnet_group_name` back to the existing production subnet group, for example `aws_db_subnet_group.prod_existing.name`. Use the actual name of the subnet group currently attached to the cluster.
   - Run `terraform plan` and confirm that `aws_rds_cluster.prod` shows no `-/+` replacement and no destroy action.
   - If the subnet group must genuinely change, plan a controlled migration with a snapshot, a restore strategy, and a maintenance window. Do not apply a ForceNew change directly to production.

2. **Block accidental destruction of the production cluster.**
   - Add `lifecycle { prevent_destroy = true }` to `aws_rds_cluster.prod`. This causes any plan that would destroy the cluster to fail rather than proceed. It is a safety net, so the plan should still be reviewed.
   - Note that `prevent_destroy` must be removed deliberately before any intentional decommissioning, so document that step in the change record.

### HIGH

3. **Enable deletion protection on `aws_rds_cluster.prod`.**
   - Add `deletion_protection = true`.
   - Apply this change separately from the subnet group fix, after the plan has been validated, so that its effect can be confirmed on its own.

### MEDIUM

4. **Export database logs to CloudWatch for `aws_rds_cluster.prod`.**
   - Set `enabled_cloudwatch_logs_exports` to the log types supported by the cluster engine. For example, use `["audit", "error", "slowquery"]` for Aurora MySQL, or `["postgresql"]` for Aurora PostgreSQL. Confirm the engine before setting this value.
   - No remediation was generated for this finding. Add it as a follow-up change.

5. **Set explicit security groups on `aws_rds_cluster.prod`.**
   - Set `vpc_security_group_ids` to a dedicated database security group that allows inbound traffic only from the application security groups on the database port.
   - No remediation was generated for this finding. Add it as a follow-up change, and confirm the current effective rules before changing the group assignment to avoid an outage.

### Cost Follow-Up

6. **Review backup retention and instance definitions.**
   - Confirm that 30-day backup retention is a requirement and not a default. Shorter retention reduces storage charges.
   - Add the `aws_rds_cluster_instance` resources to the plan or document where they are defined, so compute costs can be estimated.
