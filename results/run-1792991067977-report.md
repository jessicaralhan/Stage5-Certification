## Findings by Domain

### Infrastructure (Terraform) Findings

**Risk Level: HIGH**

#### Destructive Changes

No destructive changes were identified in the plan. No resources are scheduled for deletion or forced replacement.

#### Security Exposure

❌ **HIGH**: MFA delete is disabled on the audit-log bucket.
- **Resource**: `aws_s3_bucket_versioning.logs`
- **Exposure Type**: Unprotected log deletion
- **Issue**: Any principal with `s3:DeleteObject` or `s3:DeleteObjectVersion` can permanently remove log versions.
- **Impact**: An attacker or an insider with delete permissions can erase audit evidence, including records of their own activity, without a second authentication factor.

❌ **HIGH**: The audit-log bucket has no Object Lock configuration.
- **Resource**: `aws_s3_bucket.logs`
- **Exposure Type**: Mutable audit records
- **Issue**: CloudTrail logs are not write-once and can be altered or deleted.
- **Impact**: Log integrity cannot be guaranteed for forensic or compliance purposes. Retention controls depend entirely on IAM permissions.

⚠️ **MEDIUM**: Server access logging loops back into the same bucket.
- **Resource**: `aws_s3_bucket_logging.logs`
- **Exposure Type**: Recursive logging
- **Issue**: `target_bucket = aws_s3_bucket.logs.id` causes the bucket to log requests about itself.
- **Impact**: Log volume can grow unbounded, increasing cost and making it harder to isolate meaningful audit events. This setting also obscures the audit trail.

⚠️ **MEDIUM**: The bucket policy does not deny non-TLS requests.
- **Resource**: `aws_s3_bucket_policy.trail`
- **Exposure Type**: Unencrypted transport
- **Issue**: No explicit Deny statement applies when `aws:SecureTransport` is `false`.
- **Impact**: Requests to the audit bucket can be made over plaintext HTTP, exposing log data in transit.

ℹ️ **LOW**: The CloudTrail does not reference the dedicated KMS key.
- **Resource**: `aws_cloudtrail.main`
- **Exposure Type**: Encryption key scope
- **Issue**: `kms_key_id` is not set, so log files use bucket-default encryption instead of the dedicated audit-logs key.
- **Impact**: Log encryption is not governed by the audit-logs key policy and rotation controls.

#### Cost Impact

- **Noncurrent version accumulation**: Versioning is enabled on `aws_s3_bucket_versioning.logs` with no lifecycle configuration. Noncurrent log versions will accumulate indefinitely, increasing S3 storage costs over time.
- **CloudTrail charges**: The multi-region trail `aws_cloudtrail.main` incurs ongoing charges for management event delivery and S3 storage of log files.
- **KMS charges**: `aws_kms_key.logs` carries a customer-managed key charge. `bucket_key_enabled = true` in `aws_s3_bucket_server_side_encryption_configuration.logs` reduces per-request KMS costs.
- **Key rotation**: Enabling rotation on `aws_kms_key.logs` adds a small annual cost for rotated key material, which is negligible relative to KMS request charges.
- **Remediation cost note**: Object Lock in COMPLIANCE mode prevents lifecycle expiration of locked versions until their retention period ends. Storage growth from the lifecycle gap will therefore persist for at least the retention period.

- Changes to `aws_s3_bucket_policy.trail` and `aws_cloudtrail.main` could disrupt audit logging if applied incorrectly.
