## Infrastructure (Terraform) Findings

**Risk Level: HIGH**

### Data Protection & Resilience

❌ **HIGH**: S3 bucket lacks versioning, MFA Delete, and object lock configuration
   - **Resource**: `aws_s3_bucket.app`
   - **Issue**: The production S3 bucket is not configured with versioning or object lock, creating exposure to accidental or malicious data deletion with no recovery path
   - **Impact**: Unversioned bucket means deleted objects cannot be recovered; single delete operation can eliminate all data; no protection against ransomware or insider threats
   - **Severity**: HIGH
   - **Proposed Fix**:
     ```hcl
     resource "aws_s3_bucket_versioning" "app" {
       bucket = aws_s3_bucket.app.id
       versioning_configuration {
         status = "Enabled"
       }
     }
     
     resource "aws_s3_bucket_object_lock_configuration" "app" {
       bucket = aws_s3_bucket.app.id
       rule {
         default_retention {
           mode = "GOVERNANCE"
           days = 30
         }
       }
     }
     ```

### Audit & Compliance

❌ **HIGH**: S3 bucket does not have logging enabled
   - **Resource**: `aws_s3_bucket.app`
   - **Issue**: Access and modification logs are not being recorded for the production bucket, preventing audit trail of who accessed or changed data
   - **Impact**: No accountability for data access; cannot detect unauthorized modifications; fails compliance requirements (SOC 2, HIPAA, PCI-DSS) that mandate access logging for production data stores
   - **Severity**: HIGH
   - **Proposed Fix**:
     ```hcl
     resource "aws_s3_bucket_logging" "app" {
       bucket = aws_s3_bucket.app.id
       target_bucket = aws_s3_bucket.logs.id
       target_prefix = "access-logs/"
     }
     ```
     *Note: Requires creation of separate logging bucket to store access logs*

### Encryption & Key Management

⚠️ **MEDIUM**: S3 bucket encryption uses AWS-managed AES256 instead of customer-managed KMS key
   - **Resource**: `aws_s3_bucket_server_side_encryption_configuration.app`
   - **Issue**: Bucket is encrypted with service-managed keys (AES256) rather than customer-managed KMS keys, reducing control over key rotation and key access auditing
   - **Impact**: Reduced compliance control; cannot audit individual key usage; key rotation policy is fixed by AWS and cannot be customized; restricted ability to enforce key access policies
   - **Severity**: MEDIUM
   - **Proposed Fix**:
     ```hcl
     rule {
       apply_server_side_encryption_by_default {
         sse_algorithm     = "aws:kms"
         kms_master_key_id = aws_kms_key.s3.arn
       }
       bucket_key_enabled = true
     }
     ```
     *Note: Requires creation of customer-managed KMS key and associated key policy*

### Access Control

⚠️ **MEDIUM**: IAM policy grants overly broad S3 permissions without explicit deny safeguards
   - **Resource**: `aws_iam_role_policy.app`
   - **Issue**: Policy permits `s3:PutObject` on production bucket but lacks explicit deny statements for dangerous operations such as `PutBucketPolicy`, `DeleteBucket`, `DeleteBucketPolicy`, or `PutEncryptionConfiguration`
   - **Impact**: Role identity could inadvertently or maliciously modify bucket configuration, delete the entire bucket, or disable encryption; no guardrail against privilege creep
   - **Severity**: MEDIUM
   - **Recommended Action**: Add explicit deny statements for dangerous operations, or refactor policy to use resource-level conditions that restrict PutObject to only the objects prefix (not bucket itself):
     ```hcl
     resource "aws_iam_role_policy" "app" {
       role = aws_iam_role.app.id
       
       policy = jsonencode({
         Version = "2012-10-17"
         Statement = [
           {
             Effect = "Allow"
             Action = ["s3:PutObject"]
             Resource = "${aws_s3_bucket.app.arn}/*"
           },
           {
             Effect = "Deny"
             Action = [
               "s3:PutBucketPolicy",
               "s3:DeleteBucket",
               "s3:DeleteBucketPolicy",
               "s3:PutEncryptionConfiguration",
               "s3:DeleteBucketVersioning"
             ]
             Resource = aws_s3_bucket.app.arn
           }
         ]
       })
     }
     ```

### Implementation Guidance

1. **Versioning & Object Lock**: Apply both resources in same Terraform apply operation to ensure consistent state. Object lock requires bucket creation flag `object_lock_enabled = true` if not already set.

2. **Logging Infrastructure**: Create separate S3 bucket for logs (e.g., `aws_s3_bucket.logs`) with:
   - Lifecycle rule to transition logs to Glacier after 90 days
   - Bucket policy restricting PUT to S3 logging service principal only
   - Block Public Access enabled on the logging bucket

3. **KMS Key Setup**: 
   - Create key with `enable_key_rotation = true`
   - Attach key policy allowing S3 service to use the key for encryption
   - Document key ARN for cross-team reference

4. **IAM Policy Refinement**:
   - Review all principals attached to `aws_iam_role_policy.app` 
   - Test policy changes in non-production environment first
   - Implement least-privilege principle: allow only specific S3 prefixes, not entire bucket
