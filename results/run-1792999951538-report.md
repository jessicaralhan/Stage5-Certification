## Infrastructure (Terraform) Findings

**Risk Level: HIGH**

### Security Exposure

#### ❌ HIGH: RDS Master Password Stored in Plaintext State

- **Resource:** `aws_rds_cluster.prod`
- **Issue:** The master password is stored as a plaintext Terraform variable and persists unencrypted in the Terraform state file, with no integration to AWS Secrets Manager or state encryption enforcement.
- **Impact:** Any unauthorized access to the state file (via misconfigured S3 bucket, backup exposure, or compromised CI/CD system) directly exposes production database credentials. This violates the principle of least privilege and regulatory requirements (SOC 2, PCI-DSS, HIPAA) for credential management.
- **Recommendation:** Integrate AWS Secrets Manager to decouple credentials from Terraform state:
  1. Create the database secret manually or via separate Terraform module: `aws_secretsmanager_secret.rds_password`
  2. Update the RDS cluster configuration to reference the secret: `master_password = aws_secretsmanager_secret_version.rds_password.secret_string`
  3. Use `terraform import` to adopt the manually-created secret into state
  4. Remove the plaintext password variable from code and regenerate Terraform state
  5. Enable state encryption at rest using S3 backend encryption and DynamoDB locks

#### ⚠️ MEDIUM: KMS Key Deletion Window Set to Minimum (7 Days)

- **Resource:** `aws_kms_key.rds`
- **Issue:** The KMS key protecting the RDS cluster is configured with `deletion_window_in_days = 7`, the AWS minimum allowed value. This provides only a 7-day grace period before permanent deletion of the key, leaving no buffer for recovery from accidental `terraform destroy` runs or human error.
- **Impact:** Accidental key deletion would render all RDS data encrypted with this key permanently inaccessible, causing total data loss and service outage for any systems dependent on the production database. No recovery option would be available after the 7-day window expires.
- **Recommendation:** Increase the deletion window and enable key rotation:
  1. Update `deletion_window_in_days = 30` to provide a 30-day recovery window (industry best practice is 7–90 days depending on RPO requirements)
  2. Enable automatic key rotation: `enable_key_rotation = true`
  3. Add tags for lifecycle management: `tags = { purpose = "rds-encryption", lifecycle = "critical" }`
  4. Document the key deletion policy in runbooks for on-call teams
