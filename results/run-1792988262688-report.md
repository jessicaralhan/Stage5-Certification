## Infrastructure (Terraform) Findings

Risk Level: **HIGH**

### Destructive Changes

No destructive changes were identified. No resource replacements or deletions were flagged in the plan.

### Security Exposure

❌ **HIGH**: CloudTrail logs are not encrypted with the customer-managed key.
- **Resource**: `aws_cloudtrail.main`
- **Exposure Type**: Encryption configuration; possible delivery failure
- **Issue**: The trail has no `kms_key_id`, so logs use SSE-S3 instead of `aws_kms_key.logs`. The bucket's KMS default encryption may also cause delivery to fail if `cloudtrail.amazonaws.com` lacks `kms:GenerateDataKey` permission.
- **Impact**: Audit logs do not meet the intended key-management standard. If delivery fails, audit coverage gaps occur silently.
- **Recommendation**: Set `kms_key_id = aws_kms_key.logs.arn` and confirm the key policy grants CloudTrail the required permissions (see Unified Recommendations).

❌ **HIGH**: MFA Delete is disabled on the production audit log bucket.
- **Resource**: `aws_s3_bucket_versioning.logs`
- **Exposure Type**: Log integrity and deletion protection
- **Issue**: MFA Delete is disabled, so any principal with compromised credentials could permanently delete or overwrite log object versions.
- **Impact**: Attackers could erase evidence of their activity, undermining incident response and compliance obligations.
- **Recommendation**: Enable MFA Delete under root account control (see Unified Recommendations).

⚠️ **MEDIUM**: The audit log bucket policy does not deny insecure transport.
- **Resource**: `aws_s3_bucket_policy.trail`
- **Exposure Type**: Unencrypted access
- **Issue**: No statement denies requests where `aws:SecureTransport` is `false`, so plaintext HTTP access to the audit log bucket is not blocked.
- **Impact**: Credentials or log data could be transmitted unencrypted.
- **Recommendation**: Add a `Deny` statement for all `s3:*` actions with `Condition: { Bool: { "aws:SecureTransport": "false" } }`.

⚠️ **MEDIUM**: The TLS condition on the CloudTrail write statement uses the wrong operator.
- **Resource**: `aws_s3_bucket_policy.trail` (statement `AWSCloudTrailWrite`)
- **Exposure Type**: Policy logic error
- **Issue**: The condition uses `StringEquals` with `aws:SecureTransport = "true"` instead of a `Bool` condition, so the TLS requirement may not be enforced as intended.
- **Impact**: The intended transport restriction may not apply, creating a false sense of enforcement.
- **Recommendation**: Replace with `Condition: { Bool: { "aws:SecureTransport": "true" } }`.

⚠️ **MEDIUM**: Access logging writes into the bucket it monitors.
- **Resource**: `aws_s3_bucket_logging.logs`
- **Exposure Type**: Audit record integrity
- **Issue**: Access logs target the same bucket they monitor, creating a self-referential loop.
- **Impact**: Access logs mix with CloudTrail audit records, obscuring the audit trail and generating recursive write activity.
- **Recommendation**: Direct access logs to a separate, dedicated logging bucket.

ℹ️ **LOW**: The KMS key relies on the default key policy.
- **Resource**: `aws_kms_key.logs`
- **Exposure Type**: Key access control
- **Issue**: No explicit key policy is defined. Access depends on the default policy, which grants the account root full control and delegates to IAM without scoped grants for CloudTrail or the logs bucket.
- **Impact**: Access is broader than necessary and is not explicitly scoped to the audit logging workload.
- **Recommendation**: Define an explicit key policy that grants CloudTrail only `kms:GenerateDataKey*` and `kms:DescribeKey`, conditioned on `aws:SourceArn` matching the trail ARN.

### Cost Impact

- **`aws_s3_bucket.logs` (versioning enabled)**: Noncurrent versions accumulate indefinitely without a lifecycle rule. Add a `aws_s3_bucket_lifecycle_configuration` that expires noncurrent versions after a defined retention period that satisfies compliance requirements.
- **`aws_s3_bucket_logging.logs`**: Self-referential logging adds recurring PUT requests and storage growth in the audit bucket. Resolving the security finding above also eliminates this cost.
- **`aws_kms_key.logs`**: Adds a fixed monthly key charge plus per-request KMS charges. `bucket_key_enabled = true` reduces request volume and should be retained.
- **`aws_cloudtrail.main`**: The multi-region trail generates management event delivery costs proportional to API activity across all regions. Review whether all regions require coverage.

### Verdict: ESCALATE

The reviewer escalated because the findings touch production audit-log resources, including `aws_cloudtrail.main`, `aws_s3_bucket_versioning.logs`, `aws_kms_key.logs`, and `aws_s3_bucket_policy.trail`. Enabling MFA Delete requires root credentials and human sign-off. Any KMS or bucket policy change can break CloudTrail delivery. The adversarial reviewer also noted that the remediation placeholder was not populated in its review pass, so the proposed HCL was not validated against the plan.
