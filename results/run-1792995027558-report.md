# Infrastructure Security Review: Audit Logging Configuration

## Executive Summary

This review covered the Terraform plan for the production CloudTrail audit-logging stack, which includes the `aws_s3_bucket.logs` bucket, its versioning, logging, and bucket policy, the `aws_kms_key.logs` encryption key, and the `aws_cloudtrail.main` trail. ## Infrastructure (Terraform) Findings

Risk Level: **MEDIUM**

### Destructive Changes

No destructive changes were identified in the plan. No resource deletions or forced replacements were reported by the analyzer.

**Caution for remediation:** Object Lock must be enabled on the bucket itself. In the AWS provider, `object_lock_enabled` on `aws_s3_bucket` is typically a create-time argument, so changing it on the existing `aws_s3_bucket.logs` may force replacement of a production audit bucket. Confirm the plan action before applying any Object Lock change.

### Security Exposure

**1. aws_s3_bucket.logs: No S3 Object Lock**
- **Severity:** MEDIUM
- **Exposure type:** Log immutability
- **Impact:** Any principal with sufficient S3 permissions can delete or overwrite CloudTrail log objects. For an audit store, this undermines the evidentiary value of the logs and makes tampering difficult to detect.

**2. aws_s3_bucket_versioning.logs: MFA Delete Disabled**
- **Severity:** MEDIUM
- **Exposure type:** Version deletion without MFA
- **Impact:** A principal holding `s3:DeleteObjectVersion` can permanently remove log versions without a second factor. Combined with the absence of Object Lock, this allows permanent loss of audit history.

**3. aws_s3_bucket_logging.logs: Self-Referencing Access Logging**
- **Severity:** MEDIUM
- **Exposure type:** Log feedback loop and obscured events
- **Impact:** `target_bucket = aws_s3_bucket.logs.id` causes the audit bucket to write access logs about its own access. This inflates the bucket with noise and can mask genuine access events in CloudTrail and S3 access log analysis.

**4. aws_s3_bucket_policy.trail: No Deny for Insecure Transport**
- **Severity:** LOW
- **Exposure type:** Plaintext access
- **Impact:** The policy has no statement denying requests where `aws:SecureTransport` is `false`, so HTTP access to the audit bucket is not blocked.

**5. aws_kms_key.logs: Short Deletion Window**
- **Severity:** LOW
- **Exposure type:** Key recovery window
- **Impact:** `deletion_window_in_days = 10` leaves little time to cancel an accidental or malicious scheduled deletion of the key that encrypts all audit logs. Once the key is deleted, the logs become unrecoverable.

### Cost Impact

- **aws_s3_bucket_versioning.logs:** Retaining every object version increases storage costs over time. No lifecycle rule currently expires noncurrent versions, so costs will grow without bound.
- **aws_s3_bucket_logging.logs:** Self-referencing logs generate ongoing PUT request and storage charges as log objects accumulate in the audit bucket. Moving logs to a separate bucket removes this cost from the audit store.
- **aws_kms_key.logs:** The customer-managed key carries a fixed monthly charge plus per-request KMS costs. `bucket_key_enabled = true` on SSE-KMS reduces request costs substantially.
- **aws_cloudtrail.main:** The multi-region trail with `include_global_service_events = true` delivers management events to S3 with no additional trail charge for the first copy. Costs are driven by S3 storage and requests.

## Unified Recommendations

### MEDIUM Priority

1. **Enable S3 Object Lock on aws_s3_bucket.logs**
   - Confirm the plan action first. If `object_lock_enabled` forces replacement, plan a migration to a new bucket rather than an in-place change.
   - Use compliance or governance retention mode with a retention period set by your audit policy, and apply a default retention rule.
   - Owner decision required: the retention mode and period, because compliance mode cannot be reversed.

2. **Enable MFA Delete on aws_s3_bucket_versioning.logs**
   - MFA Delete can only be enabled by the root account using MFA, so it cannot be completed through a standard Terraform apply by a non-root principal.
   - Set `mfa_delete = "Enabled"` only after the root-account procedure is scheduled and documented. Track it as a manual step in the change record.

3. **Move access logging off aws_s3_bucket_logging.logs**
   - Change `target_bucket` to a dedicated access-log bucket (for example, `aws_s3_bucket.access_logs`) that is separate from the audit store.
   - Keep the target bucket's policy and encryption consistent with the audit bucket, and make sure it does not log to itself.

### LOW Priority

4. **Deny insecure transport in aws_s3_bucket_policy.trail**
   - Add a statement with `Effect = "Deny"`, `Principal = "*"`, `Action = "s3:*"`, applied to both the bucket ARN and the `/*` object ARN, with the condition `Bool: { "aws:SecureTransport": "false" }`.
   - Test that CloudTrail delivery still succeeds after the change.

5. **Increase the KMS deletion window on aws_kms_key.logs**
   - Set `deletion_window_in_days = 30`, the maximum allowed, so there is more time to cancel an accidental deletion.

### Cost Actions

6. **Add a lifecycle rule for noncurrent versions on aws_s3_bucket.logs**
   - Define a `noncurrent_version_expiration` rule. Choose the retention period based on the audit retention requirement, not on cost alone, because expiring noncurrent versions removes audit history.

7. **Keep bucket_key_enabled = true on the KMS-encrypted bucket.** This setting is already in place and should be preserved.

### Process Actions

9. **Assign a human reviewer** to decide the Object Lock retention policy, the MFA Delete procedure, and the access-log bucket design before the plan is re-approved.
