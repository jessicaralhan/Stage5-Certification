- **Why it matters**: Production workloads require verifiable control over encryption keys and ability to audit key access. AWS-managed keys hide this visibility.

## Unified Recommendations

### Priority 1: CRITICAL — Resolve IAM Policy Condition Gaps

**Action**: Restrict `PutObject` permission in `aws_iam_role_policy.app` with encryption and path conditions.

**Implementation**:
```json
{
  "Effect": "Allow",
  "Action": "s3:PutObject",
  "Resource": "arn:aws:s3:::bucket-name/allowed-prefix/*",
  "Condition": {
    "StringEquals": {
      "s3:x-amz-server-side-encryption": "aws:kms"
    },
    "StringLike": {
      "s3:x-amz-server-side-encryption-aws-kms-key-arn": "arn:aws:kms:REGION:ACCOUNT:key/KEY-ID"
    }
  }
}
```

**Rationale**: This prevents unencrypted uploads and restricts writes to a specific path prefix, reducing blast radius of compromised credentials.

**Timeline**: Implement before S3 bucket deployment.

---

### Priority 2: HIGH — Enable S3 Data Protection (Versioning & Object Lock)

**Action**: Add versioning and object lock to `aws_s3_bucket.app`.

**Implementation**:
```hcl
resource "aws_s3_bucket_versioning" "app" {
  bucket = aws_s3_bucket.app.id
  versioning_configuration {
    status     = "Enabled"
    mfa_delete = "Enabled"
  }
}

resource "aws_s3_bucket_object_lock_configuration" "app" {
  bucket = aws_s3_bucket.app.id
  rule {
    default_retention {
      mode = "GOVERNANCE"
      days = 30
    }
  }
}
```

**Manual Step**: AWS account root user must enable MFA delete via AWS CLI:
```bash
aws s3api put-bucket-versioning \
  --bucket bucket-name \
  --versioning-configuration Status=Enabled,MFADelete=Enabled \
  --sse-customer-algorithm AES256 \
  --sse-customer-key <root-mfa-key>
```

**Rationale**: Prevents accidental or malicious deletion; GOVERNANCE mode allows compliance officer override if needed.

**Timeline**: Complete before production traffic reaches bucket.

---

### Priority 3: HIGH — Switch to Customer-Managed KMS Encryption

**Action**: Upgrade `aws_s3_bucket_server_side_encryption_configuration.app` to use KMS instead of SSE-S3.

**Implementation**:
1. Create or identify KMS key:
   ```hcl
   resource "aws_kms_key" "s3" {
     description             = "S3 production bucket encryption key"
     deletion_window_in_days = 30
     enable_key_rotation     = true
   }
   ```

2. Update S3 encryption configuration:
   ```hcl
   resource "aws_s3_bucket_server_side_encryption_configuration" "app" {
     bucket = aws_s3_bucket.app.id
     rule {
       apply_server_side_encryption_by_default {
         sse_algorithm     = "aws:kms"
         kms_master_key_id = aws_kms_key.s3.arn
       }
       bucket_key_enabled = true
     }
   }
   ```

**Rationale**: Enables key rotation, audit logging via CloudTrail, and compliance with regulatory key control requirements.

**Timeline**: Implement in same Terraform apply as versioning changes.

### Priority 5: MEDIUM — Define S3 Lifecycle Policies

**Action**: Add lifecycle rules to `aws_s3_bucket.app` to control storage costs.

**Implementation**:
```hcl
resource "aws_s3_bucket_lifecycle_configuration" "app" {
  bucket = aws_s3_bucket.app.id

  rule {
    id     = "archive-old-versions"
    status = "Enabled"

    noncurrent_version_transition {
      noncurrent_days          = 90
      storage_class            = "GLACIER"
    }

    noncurrent_version_expiration {
      noncurrent_days = 365
    }
  }

  rule {
    id     = "cleanup-incomplete-uploads"
    status = "Enabled"

    abort_incomplete_multipart_upload {
      days_after_initiation = 7
    }
  }
}
```

**Rationale**: Transitions old object versions to cheaper storage classes and cleans up partial uploads to prevent cost overruns.

**Timeline**: Implement before production workload begins writing to bucket.
