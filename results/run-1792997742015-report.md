## Infrastructure (Terraform) Findings

Risk Level: **HIGH**

### Destructive Changes

No destructive changes were identified. No resources are scheduled for deletion or forced replacement.

### Security Exposure

❌ **HIGH**: MFA delete disabled on production audit log bucket
- **Resource**: `aws_s3_bucket_versioning.logs`
- **Exposure Type**: Unauthenticated object deletion
- **Impact**: Anyone with `s3:DeleteObjectVersion` permissions can permanently delete audit log versions without MFA verification. An attacker with compromised credentials could erase evidence of activity, which undermines incident response and compliance attestations.

⚠️ **MEDIUM**: CloudTrail bucket policy relies on bucket-level encryption only
- **Resource**: `aws_s3_bucket_policy.trail`
- **Exposure Type**: Weak encryption enforcement on write path
- **Impact**: The policy permits `s3:PutObject` from `cloudtrail.amazonaws.com` without requiring the request to specify SSE-KMS. Objects written with a non-KMS or incorrect key would not be rejected, so encryption depends entirely on the bucket default, which can be changed independently.

⚠️ **MEDIUM**: Circular access logging without retention controls
- **Resource**: `aws_s3_bucket_logging.logs`
- **Exposure Type**: Unbounded storage growth and self-referential logging
- **Impact**: The bucket writes its own access logs back into itself. This generates log-about-log growth and has no lifecycle expiration, so storage and cost increase without limit.

### Cost Impact

- **KMS key with rotation enabled**: Ongoing monthly key management charges plus per-request API charges.
- **Versioning on `aws_s3_bucket_versioning.logs`**: Noncurrent object versions increase storage costs. The lifecycle rule recommended below will contain this.
- **Multi-region CloudTrail**: Charged per 100,000 management events across all regions. Costs scale with account activity, not with the plan itself.

### Proposed Remediations

**1. MFA delete on `aws_s3_bucket_versioning.logs` (HIGH)**

The proposed fix sets `mfa_delete = "Enabled"`. Note the following before applying:
- The Terraform AWS provider requires an `mfa` argument (MFA device serial and current token code) to change `mfa_delete`. The proposed fix omits it and will fail or be unapplyable from a standard IAM role.
- MFA delete can only be enabled by the root account using its own MFA device. Plan a root-user session for this change and do not automate it through a pipeline role.
- Once enabled, version deletions require MFA, which affects any automated lifecycle or cleanup jobs. Confirm those jobs are not dependent on permanent version deletion.

**2. Encryption enforcement on `aws_s3_bucket_policy.trail` (MEDIUM)**

The proposed statement is an `Allow` with KMS conditions. An `Allow` statement does not block non-compliant uploads, so it adds no enforcement. Use a `Deny` statement instead:
- Effect: `Deny`
- Principal: `*`
- Action: `s3:PutObject`
- Resource: the actual log bucket ARN followed by `/*`
- Condition: `StringNotEquals` on `s3:x-amz-server-side-encryption` set to `aws:kms`, and `StringNotEqualsIfExists` on `s3:x-amz-server-side-encryption-aws-kms-key-id` set to the ARN of the KMS key defined in the plan.

Replace the placeholder ARN fragments (`arn:aws:s3:::bucket/*`, `arn:aws:kms:...`) with the real references from the plan before applying. Do not apply the proposal as written.

**3. Circular logging and retention on `aws_s3_bucket_logging.logs` (MEDIUM)**

- Direct access logs to a separate dedicated logging bucket (for example, `aws_s3_bucket.logs_access`), and do not log the audit bucket to itself.
- Add a lifecycle configuration to the audit log bucket, but treat the values as a compliance decision, not a default. The proposed 90-day expiration and 30-day noncurrent version expiration may be shorter than required by the applicable retention policy (for example, 1 year or longer for CloudTrail under many frameworks). Confirm the retention requirement with compliance before setting these values.
