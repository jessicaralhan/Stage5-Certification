### Overly Broad Permissions

❌ **CRITICAL**: Statement `AllowEverything` grants full administrative access.

- **Current scope**: `Action: "*"`, `Resource: "*"`
- **Impact**: Any credential bound to this statement can read, modify, or delete every database, encryption key, security group, and IAM entity in production.
- **Least-privilege target**: Replace `"Action": "*"` with the explicit action list the consuming principal requires (for example, `rds:Describe*` for read-only database inspection). Scope each action to specific ARNs rather than `"*"`.

### Missing Resource Boundaries

❌ **CRITICAL**: `AllowEverything` has no resource restrictions.
- **Affected resources**: All resources in the production account (databases, KMS keys, security groups, IAM entities, and others)
- **Impact**: A single compromised credential has blast radius across the entire account.
- **Required change**: Replace `"Resource": "*"` with ARNs for the specific databases, keys, and groups the principal needs. Where the service does not support resource-level permissions, document that limitation and compensate with conditions.

### Missing MFA/Conditions

❌ **CRITICAL**: `AllowEverything` permits destructive and privilege-changing actions (delete, create, modify) without MFA.
- **Principal**: Not identified in the policy document
- **Gap**: No `aws:MultiFactorAuthPresent` condition on destructive or IAM-modifying actions
- **Required change**: Add a condition block requiring `"Bool": {"aws:MultiFactorAuthPresent": "true"}` to any statement that allows delete, create, or modify actions.

⚠️ **HIGH**: `AllowEverything` has no network or transport conditions.
- **Gap**: No `aws:SourceIp`, `aws:RequestedRegion`, `aws:SecureTransport`, or request-tag conditions
- **Impact**: Credentials can be used from any location, at any time, over any transport.
- **Required change**: Add `aws:SecureTransport: true` at minimum. Add `aws:SourceIp` restrictions where the principal operates from known networks.
