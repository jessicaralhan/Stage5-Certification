## Infrastructure (Terraform) Findings

**Risk Level**: **MEDIUM**

### Destructive Changes

No destructive changes detected in this Terraform plan. All resources are new additions with no modifications to existing infrastructure that would trigger replacement or deletion.

### Security Exposure

#### ❌ **MEDIUM**: S3 Bucket Lacks Versioning Configuration
- **Resource**: `aws_s3_bucket.app`
- **Issue**: S3 bucket versioning is not enabled, eliminating the ability to recover from accidental or malicious object deletion.
- **Impact**: Production data loss cannot be recovered. Deleted or overwritten objects are unrecoverable, creating vulnerability to ransomware, insider threats, and accidental deletion.
- **Severity**: MEDIUM

#### ❌ **MEDIUM**: S3 Bucket Lacks Access Logging Configuration
- **Resource**: `aws_s3_bucket.app`
- **Issue**: No access logging configuration is present, preventing creation of an audit trail for bucket access and modifications.
- **Impact**: Production environment visibility is lost; cannot determine who accessed, modified, or deleted bucket contents. Compliance violations in regulated environments (HIPAA, PCI-DSS, SOC 2).
- **Severity**: MEDIUM

#### ❌ **MEDIUM**: S3 Bucket Uses AES256 Instead of KMS Encryption
- **Resource**: `aws_s3_bucket_server_side_encryption_configuration.app`
- **Issue**: Bucket encryption uses AWS-managed AES256 (server-side managed keys) instead of customer-managed KMS keys, reducing control over encryption key lifecycle and audit capabilities.
- **Impact**: Cannot rotate encryption keys independently; limited visibility into key usage; reduced compliance audit trail for key operations.
- **Severity**: MEDIUM

#### ❌ **MEDIUM**: IAM Policy Grants Unrestricted PutObject Permission
- **Resource**: `aws_iam_role_policy.app`
- **Issue**: The IAM policy permits PutObject action on the S3 bucket without resource-level restrictions or encryption enforcement conditions, allowing the role to overwrite any object in the bucket.
- **Impact**: Compromised role credentials can modify or corrupt any data in the bucket. No enforcement of encryption requirements on uploads. Violates principle of least privilege.
- **Severity**: MEDIUM

### Cost Impact

- **S3 Bucket Storage**: New S3 bucket will incur ongoing storage costs. Impact is minimal unless significant data volume is anticipated (typically $0.023/GB/month in standard tier).
- **Security Configuration**: KMS key usage for bucket encryption will incur API call costs (~$0.03 per 10,000 requests); versioning storage costs proportional to object churn rate.
- **Overall**: Negligible cost for new security group and IAM role/policy. Primary cost driver is S3 storage and versioning overhead.

## Unified Recommendations

### Priority 1: MEDIUM Severity – Enable S3 Versioning

**Action**: Add versioning configuration to `aws_s3_bucket.app`

**Implementation**:
```hcl
resource "aws_s3_bucket_versioning" "app" {
  bucket = aws_s3_bucket.app.id
  versioning_configuration {
    status = "Enabled"
  }
}
```

**Timeline**: Apply before production deployment  
**Validation**: Confirm versioning status = "Enabled" in AWS Console or via `aws s3api get-bucket-versioning`

---

### Priority 2: MEDIUM Severity – Implement S3 Access Logging

**Action**: Configure access logging for `aws_s3_bucket.app` to a dedicated logging bucket

**Implementation**: 
```hcl
resource "aws_s3_bucket" "logging" {
  bucket = "${var.app_name}-logs-${var.aws_account_id}"
}

resource "aws_s3_bucket_logging" "app" {
  bucket        = aws_s3_bucket.app.id
  target_bucket = aws_s3_bucket.logging.id
  target_prefix = "access-logs/"
}
```

**Timeline**: Apply before production deployment  
**Validation**: Verify logs appear in target bucket within 1 hour of bucket access

---

### Priority 3: MEDIUM Severity – Migrate S3 Encryption to KMS

**Action**: Replace AES256 encryption with customer-managed KMS key in `aws_s3_bucket_server_side_encryption_configuration.app`

**Implementation**:
```hcl
resource "aws_kms_key" "s3" {
  description             = "KMS key for S3 bucket encryption"
  deletion_window_in_days = 7
  enable_key_rotation     = true
}

resource "aws_s3_bucket_server_side_encryption_configuration" "app" {
  bucket = aws_s3_bucket.app.id

  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm     = "aws:kms"
      kms_master_key_id = aws_kms_key.s3.arn
    }
    bucket_key_enabled = true
  }
}
```

**Timeline**: Apply before production deployment  
**Validation**: Confirm bucket encryption rule shows KMS algorithm in AWS Console; verify key rotation is enabled

---

### Priority 4: MEDIUM Severity – Restrict IAM PutObject Permission

**Action**: Refine `aws_iam_role_policy.app` to enforce least-privilege access with prefix restriction and encryption conditions

**Implementation**:
```hcl
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "RestrictedS3Upload",
      "Effect": "Allow",
      "Action": "s3:PutObject",
      "Resource": "arn:aws:s3:::${aws_s3_bucket.app.id}/uploads/*",
      "Condition": {
        "StringEquals": {
          "s3:x-amz-server-side-encryption": "aws:kms",
          "s3:x-amz-server-side-encryption-aws-kms-key-id": "${aws_kms_key.s3.arn}"
        }
      }
    },
    {
      "Sid": "ListBucketUploads",
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::${aws_s3_bucket.app.id}",
      "Condition": {
        "StringLike": {
          "s3:prefix": ["uploads/*"]
        }
      }
    },
    {
      "Sid": "GetObjectUploads",
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::${aws_s3_bucket.app.id}/uploads/*"
    }
  ]
}
```

**Timeline**: Apply before production deployment  
**Validation**: Test role credentials; confirm uploads outside `/uploads/*` prefix are denied; confirm uploads without KMS encryption are rejected
