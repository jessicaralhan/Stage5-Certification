### Security Exposure

❌ **HIGH**: CloudTrail log delivery to the audit bucket will fail.
   - **Resource**: `aws_kms_key.logs`
   - **Exposure type**: Missing key policy for service principal `cloudtrail.amazonaws.com`
   - **Issue**: The key has no policy granting `kms:GenerateDataKey*` and `kms:Decrypt` to CloudTrail.
   - **Impact**: CloudTrail writes to the SSE-KMS-encrypted bucket will fail, so audit events will not be recorded. This is a direct audit coverage gap.

⚠️ **MEDIUM**: Server access logging is self-referential.
   - **Resource**: `aws_s3_bucket_logging.logs`
   - **Exposure type**: Logging target equals the logged bucket; no bucket policy grant for `logging.s3.amazonaws.com`
   - **Impact**: Log delivery is unreliable, and log objects pollute the audit bucket itself.

⚠️ **MEDIUM**: Non-TLS access to the audit bucket is not explicitly denied.
   - **Resource**: `aws_s3_bucket_policy.trail`
   - **Exposure type**: Missing Deny on `aws:SecureTransport = false`
   - **Impact**: Requests over plaintext HTTP are not blocked for all principals, weakening in-transit protection of audit data.

⚠️ **MEDIUM**: Audit log objects can be permanently deleted.
   - **Resource**: `aws_s3_bucket.logs`
   - **Exposure type**: Versioning without MFA Delete and without Object Lock
   - **Impact**: Any principal with `s3:DeleteObject` can permanently remove audit logs, which undermines non-repudiation.

🔹 **LOW**: CloudTrail does not use a CloudTrail-managed KMS key.
   - **Resource**: `aws_cloudtrail.main`
   - **Exposure type**: `kms_key_id` not set
   - **Impact**: Trail log files rely only on bucket default encryption rather than a dedicated key.

🔹 **LOW**: Short KMS key deletion recovery window.
   - **Resource**: `aws_kms_key.logs`
   - **Exposure type**: `deletion_window_in_days = 10` (close to the 7-day minimum)
   - **Impact**: An accidental or malicious deletion schedule leaves little time to recover, and encrypted audit logs would become unreadable.

🔹 **LOW**: Confused-deputy boundary is weaker than recommended.
   - **Resource**: `aws_s3_bucket_policy.trail`
   - **Exposure type**: CloudTrail statements condition on `aws:SourceAccount` but not `aws:SourceArn`
   - **Impact**: Weaker protection against cross-account service misuse than recommended.

### Cost Impact

- **`aws_s3_bucket.logs`**: Versioning without a lifecycle rule will accumulate noncurrent object versions and steadily increase S3 storage cost.
- **`aws_s3_bucket_logging.logs`**: Self-targeted access logs add storage and request charges to the versioned audit bucket.
- **`aws_kms_key.logs`**: The customer-managed key incurs a monthly key fee plus per-request KMS charges. `bucket_key_enabled = true` reduces request costs.
- **`aws_cloudtrail.main`**: The multi-region trail with log file validation adds S3 storage and PUT request costs proportional to API activity across all regions.

## Unified Recommendations

### HIGH (Priority 1): Restore CloudTrail delivery to the audit bucket

- **Resource**: `aws_kms_key.logs`
- **Action**: Add a key policy statement that allows the `cloudtrail.amazonaws.com` service principal to perform `kms:GenerateDataKey*` and `kms:Decrypt`. Scope the statement with an `aws:SourceArn` condition matching the trail ARN for `aws_cloudtrail.main`, and an `aws:SourceAccount` condition matching the account ID. Keep the existing account-root administrative statement so the key remains manageable.
- **Verification**: After apply, confirm that new objects are written to the bucket and that the trail reports healthy delivery status. Confirm with a test API call that a new log file appears within the expected delivery window.

### HIGH (Priority 1, same change set): Fix KMS deletion protection

- **Resource**: `aws_kms_key.logs`
- **Action**: Increase `deletion_window_in_days` from 10 to 30, the maximum, to allow more time to recover from an accidental or malicious deletion request.

### MEDIUM (Priority 2): Block non-TLS access and tighten the trail policy

- **Resource**: `aws_s3_bucket_policy.trail`
- **Action**: Add an explicit `Deny` statement for all principals (`Principal: "*"`) on `s3:*` for the bucket and its objects, with the condition `Bool: { "aws:SecureTransport": "false" }`.
- **Action**: Add `aws:SourceArn` conditions to the CloudTrail statements alongside the existing `aws:SourceAccount` conditions, to tighten the confused-deputy boundary.

### MEDIUM (Priority 2): Protect audit objects from deletion

- **Resource**: `aws_s3_bucket.logs`
- **Action**: Enable Object Lock with a retention policy appropriate to your compliance requirements. Compliance mode is preferred for audit data because it prevents deletion even by the account root user. Object Lock must be enabled at bucket creation, so this may require creating a new bucket and migrating data.
- **Action**: Enable MFA Delete. Note that AWS allows only the root account to enable it, and only through the CLI or API, so schedule this as a privileged manual step.

### MEDIUM (Priority 2): Move server access logs out of the audit bucket

- **Resource**: `aws_s3_bucket_logging.logs`
- **Action**: Point the logging target at a separate, dedicated access-log bucket that is not the audit bucket. Add a bucket policy on that target granting `logging.s3.amazonaws.com` `s3:PutObject` with an `aws:SourceAccount` condition.
