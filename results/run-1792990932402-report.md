### Overly Broad Permissions

❌ **CRITICAL**: Wildcard administrator grant on all actions and resources
- **Policy**: `AllowEverything` (principal not identified in the output)
- **Current scope**: `Action: "*"` on `Resource: "*"`, covering IAM, KMS, billing, and all other services
- **Impact**: Any credential bound to this policy can read or modify every resource in the account, including IAM users and roles, encryption keys, databases, and security groups. Compromise of that credential is equivalent to full account compromise.
- **Least-privilege target**: Replace the wildcard with an explicit allow list of read-only operational actions (for example, `ec2:Describe*`, `rds:Describe*`, `cloudwatch:Get*`, `logs:Get*`, `logs:Describe*`) scoped to the specific resource ARNs the principal needs. Any write permissions should be granted in a separate statement with narrower resources and conditions. Explicitly exclude `iam:*`, `kms:*`, and `organizations:*` from any broad grant.

### Missing Resource Boundaries

❌ **CRITICAL**: Policy applies to every resource in the account
- **Policy**: `AllowEverything`
- **Affected resources**: `*` (databases, encryption keys, security groups, and all other resources)
- **Impact**: There is no resource-level containment. A single over-privileged identity can reach production data stores and key material directly.
- **Required change**: Specify resource ARNs for each statement, such as `arn:aws:ec2:<region>:<account-id>:instance/<instance-id>`. Keep KMS key and IAM resources out of operational statements entirely.

### Missing MFA/Conditions

❌ **CRITICAL**: No MFA requirement for destructive actions
- **Principal**: Unnamed principal attached to `AllowEverything`
- **Gap**: No `aws:MultiFactorAuthPresent` condition. Create, delete, and modify actions can run with a stolen long-term or session credential.
- **Required change**: Add `"Condition": {"Bool": {"aws:MultiFactorAuthPresent": "true"}}` to any statement that permits mutating actions.

❗ **HIGH**: No origin or transport restrictions
- **Principal**: Unnamed principal attached to `AllowEverything`
- **Gap**: No source IP, time window, or `aws:SecureTransport` condition. Access is not limited by network origin or hour.
- **Required change**: Add `aws:SourceIp` restrictions to CIDRs for corporate or VPN egress, add `aws:SecureTransport: true`, and add a time-window condition where operational access is not needed around the clock.
