### Security Exposure

#### ❌ **HIGH**: S3 Bucket Missing Versioning and MFA Delete Protection
- **Resource:** `aws_s3_bucket.app`
- **Issue:** S3 bucket versioning and MFA delete are not explicitly enabled, creating risk of unrecoverable data loss in production.
- **Severity:** HIGH
- **Impact:** Without versioning, accidental or malicious deletion of production data cannot be recovered. MFA delete adds an additional authentication layer to prevent unauthorized permanent deletion. This is a critical gap for production workloads.
- **Recommendation:** Enable versioning on the bucket and configure MFA delete to require multi-factor authentication for object deletion. Update the Terraform resource to include:
  ```hcl
  versioning {
    enabled = true
    mfa_delete = true
  }
  ```

#### ❌ **MEDIUM**: S3 Bucket Missing Object Lock
- **Resource:** `aws_s3_bucket.app`
- **Issue:** S3 bucket does not have object lock enabled, allowing accidental or malicious deletion of production data.
- **Severity:** MEDIUM
- **Impact:** Object Lock provides a write-once-read-many (WORM) model that prevents deletion or modification for a specified retention period. Without it, there is no additional technical control against data destruction.
- **Recommendation:** Enable Object Lock on the S3 bucket with either compliance mode (immutable even by root user) or governance mode (modifiable with appropriate permissions). Add to Terraform:
  ```hcl
  object_lock_enabled = true
  object_lock_configuration {
    rule {
      default_retention {
        mode = "COMPLIANCE"
        days = 90
      }
    }
  }
  ```

#### ❌ **MEDIUM**: Encryption Uses AWS-Managed Keys Instead of Customer-Managed KMS
- **Resource:** `aws_s3_bucket_server_side_encryption_configuration.app`
- **Issue:** Encryption uses AES256 (AWS-managed) instead of customer-managed KMS, limiting audit and control over production encryption keys.
- **Severity:** MEDIUM
- **Impact:** With AWS-managed encryption, key rotation and audit trails are controlled by AWS. Customer-managed KMS keys provide full control over key lifecycle, rotation schedules, and CloudTrail logging of all encryption operations. This is required for organizations with strict compliance requirements.
- **Recommendation:** Create a customer-managed KMS key and update the S3 bucket encryption configuration to use it:
  ```hcl
  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm      = "aws:kms"
      kms_master_key_id  = aws_kms_key.s3_app.arn
    }
    bucket_key_enabled = true
  }
  ```
  Enable CloudTrail logging for all KMS operations.

#### ❌ **MEDIUM**: S3 Bucket Access Logging Not Configured
- **Resource:** `aws_s3_bucket.app`
- **Issue:** S3 bucket access logging is not configured, preventing audit trail of production data access.
- **Severity:** MEDIUM
- **Impact:** Without access logging, there is no record of who accessed which objects, when, or from which IP address. This breaks compliance audit trails and makes security incident investigation impossible.
- **Recommendation:** Enable S3 access logging to a dedicated logging bucket:
  ```hcl
  logging {
    target_bucket = aws_s3_bucket.logging.id
    target_prefix = "app-bucket-logs/"
  }
  ```
  Implement lifecycle policies on the logging bucket to archive logs after 90 days and delete after 7 years per compliance requirements.

#### ❌ **MEDIUM**: IAM Policy Grants s3:PutObject Without Conditions
- **Resource:** `aws_iam_role_policy.app`
- **Issue:** IAM policy grants `s3:PutObject` without conditions, allowing the role to overwrite any object under `/data/` prefix in production.
- **Severity:** MEDIUM
- **Impact:** The role can overwrite any existing object, potentially corrupting production data or replacing legitimate objects with malicious content. This violates the principle of least privilege.
- **Recommendation:** Add condition to restrict PutObject to new objects only or specific tags:
  ```json
  {
    "Action": "s3:PutObject",
    "Effect": "Allow",
    "Resource": "arn:aws:s3:::app-bucket/data/*",
    "Condition": {
      "StringEquals": {
        "s3:x-amz-tagging": "environment=production"
      },
      "Null": {
        "s3:x-amz-copy-source": "true"
      }
    }
  }
  ```
  Alternatively, restrict to a specific date prefix or version ID check to prevent overwrites.
