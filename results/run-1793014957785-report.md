## Infrastructure (Terraform) Findings

**Risk Level: CRITICAL**

### Destructive Changes

❌ **CRITICAL**: Production RDS cluster scheduled for destroy-and-recreate.
- **Resource**: `aws_rds_cluster.prod`
- **Forcing Attribute**: `db_subnet_group_name`
- **Environment**: Production
- **Impact**: Unplanned database outage, potential data loss if backups are not current, connection disruption to all dependent applications, compliance violations if SLAs require continuous availability.
- **Why This Matters**: RDS cluster replacement is a destructive operation that terminates all active connections, deletes the database instance, and recreates it from scratch. The change appears to be triggered by a modification to the subnet group assignment, which should not force cluster replacement under normal circumstances.

### Security Exposure

⚠️ **MEDIUM**: RDS cluster uses AWS-managed encryption instead of customer-managed KMS key.
- **Resource**: `aws_rds_cluster.prod`
- **Issue**: Encryption at rest is enabled but defaults to AWS-managed key (aws/rds) because no customer-managed KMS key is specified.
- **Impact**: Reduced control over encryption key lifecycle, audit logging, and rotation policies. Does not meet compliance requirements for customer-managed key separation of duties (e.g., SOC 2, PCI-DSS, HIPAA).
- **Recommendation**: Provision a dedicated `aws_kms_key` for RDS encryption and specify it in the cluster's `kms_key_id` parameter. Implement key rotation policy (annual or as required by compliance framework).

⚠️ **MEDIUM**: RDS cluster authentication relies on password-only access.
- **Resource**: `aws_rds_cluster.prod`
- **Issue**: IAM database authentication is disabled. All database connections require username/password credentials stored in application config or secrets manager.
- **Impact**: Increased risk of credential exposure through logs, version control, or misconfigured secret storage. No native audit trail of which IAM principal authenticated. Violates least-privilege access principles.
- **Recommendation**: Enable IAM database authentication by setting `enable_iam_database_authentication = true` in the RDS cluster configuration. Update application connection strings to use temporary credentials issued by IAM. This provides native integration with AWS audit logging (CloudTrail) and removes static credential management.

### Cost Impact

- **New KMS Key**: `aws_kms_key.rds` will incur approximately $1/month for key storage plus per-API-call charges for encryption/decryption operations (typically $0.03 per 10,000 requests).
- **Cluster Replacement**: Destroying and recreating the RDS cluster will trigger data transfer charges during failover/migration and potential downtime-related costs depending on SLA penalties.
