## Unified Recommendations

### CRITICAL

1. **Identify the principal and its consumers.** Determine which user, role, or service principal holds the `AllowEverything` statement. List every trust relationship and every role it can assume. Owner: IAM/security team. Do this before any policy change.
2. **Confirm usage.** Pull IAM last-accessed data for the principal over at least 90 days. If it is unused, detach `AllowEverything` and disable or delete the principal. If it is used, record the actual action and resource set it calls.
3. **Replace the wildcard statement with a scoped policy.** Build the replacement from observed usage, not from the generator's proposed action list alone. Start with the scoped actions and resources in the Findings section, verify each ARN and account ID against live infrastructure, and remove `iam:*`, `sts:AssumeRole`, and `organizations:*` unless there is a documented need.
4. **Apply the change in a non-production account first.** Validate that the scoped policy does not break deployments, backups, or service-role calls. Only then roll it out to production, with the original `AllowEverything` statement removed in the same change window.
5. **Obtain security sign-off before production changes.** This is the escalation point identified by the reviewer.

### HIGH

6. **Add a permissions boundary** to the principal that caps its maximum effective permissions, so future policy attachments cannot restore broad access.
7. **Scope MFA and source-IP conditions to sensitive actions only.** Apply `aws:MultiFactorAuthPresent` (and `aws:MultiFactorAuthAge` where appropriate) to IAM modification, KMS administration, and data deletion actions. Do not apply a blanket source-IP restriction without first mapping all automation and AWS-service call paths, including `aws:ViaAWSService`. Validate in staging.

### MEDIUM

8. **Set session duration limits.** Reduce maximum session duration for the role or user (for example, via `MaxSessionDuration` on the role, or shorter STS session durations for federated users) to the minimum the workload requires. This addresses the unmitigated session TTL finding.

### LOW

9. **Establish a recurring access review.** Schedule quarterly reviews of administrator-level policies and unused principals, and alert on any new policy containing `Action: "*"` or `Resource: "*"`.
