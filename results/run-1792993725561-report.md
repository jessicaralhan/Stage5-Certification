## Findings by Domain

### Infrastructure (Terraform) Findings

**Risk Level:** **HIGH**

#### Destructive Changes

No destructive changes were identified in this plan.

#### Security Exposure

❌ **HIGH**: MFA delete is disabled on the production audit-log bucket.
- **Resource**: `aws_s3_bucket_versioning.logs`
- **Exposure Type**: Log tampering and deletion
- **Impact**: Any principal with `s3:DeleteObjectVersion` can permanently erase log versions, which undermines the integrity of the audit trail. Enabling MFA delete requires an MFA code at delete time, which blocks unattended or compromised-credential deletion.
- **Recommendation**: Enable `mfa_delete = "Enabled"`, and attach a Service Control Policy that denies `s3:DeleteObjectVersion` for all principals except a dedicated break-glass role. See the implementation notes below.

⚠️ **MEDIUM**: Bucket policy does not deny non-TLS requests.
- **Resource**: `aws_s3_bucket_policy.trail`
- **Exposure Type**: Unencrypted transport
- **Impact**: Requests made over plain HTTP are not explicitly blocked, so log data could be read or written without TLS.
- **Recommendation**: Add a `Deny` statement with `Principal: "*"`, `Action: "s3:*"`, and `Resource` set to both the bucket ARN and `${bucket_arn}/*`, with condition `Bool: { "aws:SecureTransport": "false" }`.

⚠️ **MEDIUM**: S3 Object Lock is not configured on the audit-log bucket.
- **Resource**: `aws_s3_bucket.logs`
- **Exposure Type**: Premature deletion or overwrite
- **Impact**: Log objects can be overwritten or deleted before retention requirements are met, which may fail compliance obligations.
- **Recommendation**: Set `object_lock_enabled = true` and define a default retention rule (mode and period per compliance policy). Object Lock cannot be enabled on an existing bucket that was created without it, so this change requires creating a new bucket, migrating logs, and updating the CloudTrail destination. Plan this as a migration, not an in-place change.

⚠️ **MEDIUM**: No explicit KMS key policy is defined.
- **Resource**: `aws_kms_key.logs`
- **Exposure Type**: Overly broad key access
- **Impact**: The default key policy grants access to any IAM principal in the account that holds KMS permissions, which weakens separation of duties over the logs.
- **Recommendation**: Define an explicit `policy` on the key that grants administrative actions only to a named security administrator role. Grant `kms:Decrypt` and `kms:GenerateDataKey*` only to the CloudTrail service principal (`cloudtrail.amazonaws.com`) and to named log-reader roles, with conditions on `kms:EncryptionContext:aws:cloudtrail:arn`.

⚠️ **MEDIUM**: Access logging writes back into the bucket it monitors.
- **Resource**: `aws_s3_bucket_logging.logs`
- **Exposure Type**: Recursive write loop and audit trail integrity
- **Impact**: Each access log write generates another access log entry, which inflates the log volume and makes the audit trail harder to read and verify.
- **Recommendation**: Create a separate, dedicated access-log bucket with its own lifecycle and restricted access, and set `target_bucket` on `aws_s3_bucket_logging.logs` to that bucket.

#### Cost Impact

💲 **Cost**: KMS charges for `aws_kms_key.logs`
- A customer-managed key adds a monthly key charge plus per-request charges. `bucket_key_enabled = true` on `aws_s3_bucket_server_side_encryption_configuration.logs` reduces the request volume, which partly offsets the cost.

💲 **Cost**: Unbounded version growth on `aws_s3_bucket.logs`
- Versioning is enabled with no lifecycle rules, so noncurrent log versions accumulate indefinitely. Add a lifecycle rule that transitions noncurrent versions to a cheaper storage class and expires them after the retention period required by policy.

💲 **Cost**: Self-logging write amplification on `aws_s3_bucket.logs`
- Access logs written into the same bucket add PUT request and storage charges, and these compound with version growth. Resolved by the dedicated log-bucket change above.

💲 **Cost**: CloudTrail delivery in `aws_cloudtrail.main`
- With `is_multi_region_trail = true`, one copy of management events is delivered free per region, but S3 storage and request costs apply to every delivered log file across all regions.
