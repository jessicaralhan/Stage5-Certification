## Unified Recommendations

**1. CRITICAL: Stop the destroy-and-recreate of `aws_rds_cluster.prod`.**
- Revert `db_subnet_group_name` to the existing subnet group name in the configuration.
- Add `lifecycle { prevent_destroy = true }` to `aws_rds_cluster.prod`. Terraform will then fail any plan that tries to destroy the cluster, which acts as a guardrail for future changes.
- If the subnet group rename is required, do not apply it in place. Create the new subnet group as a separate resource, then cut over to a cluster restored from a snapshot during a planned change window. Take and verify a final snapshot before cutover.
- Confirm the plan shows no `destroy` or `replace` actions for `aws_rds_cluster.prod` before any apply.

**2. HIGH: Enable deletion protection on `aws_rds_cluster.prod`.**
- Set `deletion_protection = true`. This adds an AWS-side safeguard that blocks deletion even if the Terraform guardrail is removed.

**3. HIGH: Declare a dedicated security group for `aws_rds_cluster.prod`.**
- Create `aws_security_group.rds_prod` with inbound rules only on the database port from the application security group. Do not allow inbound traffic from CIDR ranges or from the default security group.
- Set `vpc_security_group_ids = [aws_security_group.rds_prod.id]` on the cluster.
- Verify the effective ingress after apply by checking the cluster's attached security groups.

**4. MEDIUM (advisory): Export database logs to CloudWatch.**
- Set `enabled_cloudwatch_logs_exports` on `aws_rds_cluster.prod` to include the audit, error, and slow query log types supported by the engine. Confirm the exact list against the engine version in use.

**5. MEDIUM (advisory): Replace the default master username.**
- Change `master_username` from `"admin"` to a non-default name. Because changing the master username forces replacement, do not make this change in the same plan as the subnet group fix. Schedule it with the snapshot-restore cutover in item 1, or manage it through a separate planned change.
- Store the master credential in AWS Secrets Manager, or use RDS-managed master passwords, so that no static password appears in Terraform state or source code.
