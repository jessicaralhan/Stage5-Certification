### Security Exposure

#### 1. S3 Bucket Missing Versioning and Object Lock
- **Resource:** `aws_s3_bucket.app`
- **Severity:** 🔴 **HIGH**
- **Issue:** S3 bucket lacks versioning, MFA delete, and object lock configuration, increasing risk of accidental or malicious data deletion in production.
- **Impact:** Production data is vulnerable to permanent loss without recovery options. Malicious actors or user error can delete critical objects without audit trail or ability to restore. Compliance frameworks (HIPAA, PCI-DSS, SOC2) require immutable retention for sensitive data.
- **Business Risk:** Unrecoverable data loss in production environment; regulatory non-compliance.

#### 2. S3 Bucket Missing Access and Modification Logging
- **Resource:** `aws_s3_bucket.app`
- **Severity:** ⚠️ **MEDIUM**
- **Issue:** S3 bucket does not have logging enabled, preventing audit trail of access and modifications to production data.
- **Impact:** No visibility into who accessed, modified, or deleted bucket objects. Incident investigation, compliance audits, and forensic analysis become impossible. Security incidents cannot be traced to root cause.
- **Business Risk:** Regulatory audit failures; inability to detect or respond to unauthorized access.

#### 3. S3 Encryption Using AES256 Instead of KMS
- **Resource:** `aws_s3_bucket_server_side_encryption_configuration.app`
- **Severity:** ⚠️ **MEDIUM**
- **Issue:** S3 bucket encryption uses AES256 instead of KMS, limiting key rotation, audit, and compliance control in production.
- **Impact:** AWS-managed encryption keys cannot be rotated on demand or audited through CloudTrail. No ability to enforce encryption key policies, restrict key usage by IAM principal, or meet compliance requirements for customer-managed encryption keys. Key compromise cannot be mitigated through rotation.
- **Business Risk:** Reduced encryption control for regulated workloads; compliance gaps for FedRAMP, HIPAA, or PCI-DSS.

#### 4. IAM Policy Grants Unrestricted S3 Object Overwrites
- **Resource:** `aws_iam_role_policy.app`
- **Severity:** 🔴 **HIGH**
- **Issue:** IAM policy grants `s3:PutObject` permission on data path without conditions, allowing unrestricted object overwrites in production bucket.
- **Impact:** Any principal assuming this IAM role can overwrite any object in the bucket without encryption enforcement, versioning checks, or metadata validation. Malicious insiders or compromised applications can silently replace production data. No requirement to use KMS-encrypted uploads.
- **Business Risk:** Insider threat vector; data integrity compromise; ransomware-like attack surface.

### Cost Impact

- **S3 Bucket Creation:** Storage and request costs will be incurred. Encryption with AES256 has minimal cost impact. Upgrading to KMS encryption will add ~$1/month per customer-managed KMS key plus $0.03 per 10,000 API calls.
- **IAM Role & Security Group:** Negligible cost impact.

### Remediations

#### Priority 1: Restrict IAM Policy PutObject Permission (HIGH)
- **Resource:** `aws_iam_role_policy.app`
- **Current Issue:** Unconditional `s3:PutObject` allows any object overwrite.
- **Proposed Fix:**
  ```
  Add Condition block to restrict PutObject to KMS-encrypted uploads:
  "Condition": {
    "StringEquals": {
      "s3:x-amz-server-side-encryption": "aws:kms"
    }
  }
  ```
  Alternatively, scope Statement Resource to specific prefixes:
  ```
  "Resource": "arn:aws:s3:::bucket/prod/restricted/*"
  ```
  **Recommendation:** Implement both—restrict to specific prefixes AND require KMS encryption.
- **Implementation Type:** Configuration change
- **Effort:** 15 minutes

#### Priority 2: Enable S3 Versioning and Object Lock (HIGH)
- **Resource:** `aws_s3_bucket.app`
- **Current Issue:** No versioning or object lock; deleted objects cannot be recovered.
- **Proposed Fix:**
  ```hcl
  resource "aws_s3_bucket_versioning" "app" {
    bucket = aws_s3_bucket.app.id
    versioning_configuration {
      status = "Enabled"
    }
  }
  
  resource "aws_s3_bucket_object_lock_configuration" "app" {
    bucket = aws_s3_bucket.app.id
    rule {
      default_retention {
        mode = "GOVERNANCE"
        days = 30
      }
    }
  }
  ```
  **Note:** Object lock must be enabled at bucket creation time. If bucket exists, create new bucket with lock enabled and migrate data.
- **Implementation Type:** Configuration change (or bucket recreation)
- **Effort:** 30 minutes; may require data migration planning

#### Priority 3: Upgrade to KMS-Managed Encryption (HIGH)
- **Resource:** `aws_s3_bucket_server_side_encryption_configuration.app`
- **Current Issue:** AES256 lacks key rotation, audit, and compliance controls.
- **Proposed Fix:**
  ```hcl
  resource "aws_kms_key" "s3" {
    description             = "KMS key for S3 bucket encryption"
    deletion_window_in_days = 30
    enable_key_rotation     = true
  }
  
  resource "aws_s3_bucket_server_side_encryption_configuration" "app" {
    bucket = aws_s3_bucket.app.id
    rule {
      apply_server_side_encryption_by_default {
        sse_algorithm     = "aws:kms"
        kms_master_key_id = aws_kms_key.s3.arn
      }
    }
  }
  ```
  **Recommendation:** Enable key rotation (`enable_key_rotation = true`) and set deletion window to 30+ days for safety.
- **Implementation Type:** Configuration change
- **Effort:** 20 minutes; verify no KMS policy conflicts

#### Priority 4: Enable S3 Access Logging (MEDIUM)
- **Resource:** `aws_s3_bucket.app`
- **Current Issue:** No logging; access audit trail unavailable.
- **Proposed Fix:**
  ```hcl
  resource "aws_s3_bucket" "app_logs" {
    bucket = "app-logs-bucket"
  }
  
  resource "aws_s3_bucket_logging" "app" {
    bucket        = aws_s3_bucket.app.id
    target_bucket = aws_s3_bucket.app_logs.id
    target_prefix = "access-logs/"
  }
  ```
  **Recommendation:** Store logs in separate bucket with separate lifecycle policies (e.g., delete after 90 days).
- **Implementation Type:** Configuration change
- **Effort:** 20 minutes
