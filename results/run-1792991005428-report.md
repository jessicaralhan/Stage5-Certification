- **aws_cloudtrail.main** (LOW): No kms_key_id is set, so CloudTrail log files are not encrypted with the dedicated customer-managed KMS key and rely only on bucket-level default encryption.
- **aws_kms_key.logs** (LOW): No key policy is defined, so the key uses the AWS default policy and access to the key is not explicitly scoped to CloudTrail or named administrators.

- The customer-managed KMS key adds a fixed monthly key charge plus per-request KMS costs, partly offset by bucket_key_enabled = true reducing KMS request volume.
- Enabling bucket versioning on the audit log bucket will increase S3 storage cost over time because noncurrent versions accumulate without a lifecycle rule.
- The self-targeted access logging on aws_s3_bucket_logging.logs can generate additional S3 request and storage charges that grow with bucket activity.

### Security Exposure

❌ **MEDIUM**: CloudTrail write allow may silently fail to evaluate
- **Resource**: `aws_s3_bucket_policy.trail`
- **Exposure type**: Policy logic error (condition operator mismatch)
- **Issue**: The PutObject condition compares the boolean key `aws:SecureTransport` with `StringEquals` and the string `"true"` instead of a `Bool` operator.
- **Impact**: CloudTrail writes may stop evaluating correctly, which would silently halt audit logging. Audit gaps may go unnoticed until the logs are needed.

❌ **MEDIUM**: Non-TLS access to audit log bucket is not denied
- **Resource**: `aws_s3_bucket_policy.trail`
- **Exposure type**: Missing transport encryption enforcement
- **Issue**: No statement denies requests where `aws:SecureTransport` is `false`.
- **Impact**: Audit logs could be read or written over unencrypted HTTP, exposing log contents in transit.

❌ **MEDIUM**: MFA delete disabled on audit log versions
- **Resource**: `aws_s3_bucket_versioning.logs`
- **Exposure type**: Missing deletion safeguard
- **Issue**: `mfa_delete = "Disabled"`, so any principal with `s3:DeleteObjectVersion` can permanently purge audit log versions.
- **Impact**: An attacker or misconfigured principal could destroy audit evidence, undermining incident investigation and compliance.

⚠️ **LOW**: Self-referential server access logging
- **Resource**: `aws_s3_bucket_logging.logs`
- **Exposure type**: Log integrity and storage growth
- **Issue**: `target_bucket = aws_s3_bucket.logs.id` writes access logs into the same bucket being logged.
- **Impact**: Access logs can obscure audit data and cause unpredictable storage growth.

⚠️ **LOW**: CloudTrail not encrypted with customer-managed key
- **Resource**: `aws_cloudtrail.main`
- **Exposure type**: Encryption configuration
- **Issue**: `kms_key_id` is not set, so log files rely only on bucket default encryption rather than the dedicated key `aws_kms_key.logs`.
- **Impact**: Encryption control is weaker than intended, and key access auditing and separation of duties are reduced.

⚠️ **LOW**: KMS key uses default AWS key policy
- **Resource**: `aws_kms_key.logs`
- **Exposure type**: Overly permissive key access
- **Issue**: No key policy is defined, so access falls back to the AWS default policy and is not scoped to CloudTrail or named administrators.
- **Impact**: Key usage is not explicitly restricted, which weakens least-privilege control over the log encryption key.

### Cost Impact
