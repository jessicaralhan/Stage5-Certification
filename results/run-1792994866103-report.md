## Infrastructure (Terraform) Findings

**Risk Level**: MEDIUM

### Security Exposure
- **aws_s3_bucket_logging.logs** (MEDIUM): Server access logging targets the same bucket (aws_s3_bucket.logs.id), which can create a self-referential log loop that pollutes the audit bucket.
- **aws_s3_bucket_versioning.logs** (MEDIUM): MFA delete is disabled (mfa_delete = "Disabled"), so object versions in the audit log bucket can be permanently deleted without MFA.
- **aws_s3_bucket.logs** (MEDIUM): No S3 Object Lock is configured, so audit log objects can be overwritten or deleted by any principal with delete permissions.
- **aws_cloudtrail.main** (LOW): No kms_key_id is set on the trail, so CloudTrail log files rely only on the bucket default SSE-KMS rather than an explicitly managed CloudTrail encryption key.
- **aws_kms_key.logs** (LOW): No explicit key policy is defined, so access to the key falls back to the default policy and is not explicitly restricted to the CloudTrail and S3 principals.

### Cost Impact
- Versioning is enabled on aws_s3_bucket.logs with no lifecycle configuration, so noncurrent versions of audit logs will accumulate and increase S3 storage cost over time.
- Self-targeted access logging on aws_s3_bucket_logging.logs can generate recursive log objects that grow S3 request and storage costs.
- aws_kms_key.logs adds a customer-managed key with a flat monthly fee, but bucket_key_enabled = true on the SSE configuration reduces per-request KMS charges.
- aws_cloudtrail.main is a multi-region trail, so log delivery and storage costs scale with API activity across all regions.
