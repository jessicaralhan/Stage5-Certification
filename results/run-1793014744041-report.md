### Security Exposure

❌ **HIGH**: Missing explicit KMS key specification for RDS encryption  
- **Resource**: `aws_rds_cluster.prod`  
- **Issue**: RDS cluster has `storage_encrypted = true` but does not explicitly reference a KMS key ID. AWS uses the default AWS-managed RDS key instead of customer-managed encryption.  
- **Severity**: HIGH  
- **Impact**: Encryption key lifecycle is not under organizational control. Key rotation policies, audit logging, and access revocation cannot be implemented. Compliance frameworks (SOC 2, PCI-DSS, HIPAA) typically require customer-managed keys for sensitive data.  
- **Why This Matters**: Default AWS-managed keys do not provide the same audit trail, access control, or compliance posture as customer-managed KMS keys. Cost notes indicate `aws_kms_key.rds` is being created separately; this key must be explicitly referenced in the RDS cluster configuration.

⚠️ **MEDIUM**: IAM database authentication disabled  
- **Resource**: `aws_rds_cluster.prod`  
- **Issue**: `iam_database_authentication_enabled = false`  
- **Severity**: MEDIUM  
- **Impact**: Database access requires static passwords only. Temporary, short-lived IAM credentials cannot be used. Password rotation, audit logging of individual database access, and revocation of access without password changes are not available.  
- **Why This Matters**: Production databases should enforce IAM authentication to leverage identity federation, automated credential rotation, and fine-grained access control. This reduces risk of credential compromise and improves audit capabilities.

### Cost Impact

- **New KMS key** (`aws_kms_key.rds` with key rotation enabled): Incurs KMS API call costs for encryption/decryption operations and monthly key storage fees.
- **New DB subnet group** (`aws_db_subnet_group.prod`): Minimal standalone cost; primarily contributes to operational overhead.
- **RDS cluster** (Aurora MySQL, 30-day backup retention): Ongoing storage, backup, and compute costs; forced replacement will temporarily double costs during recovery period.

### 2. 🔴 HIGH — Integrate Customer-Managed KMS Key with RDS Encryption

**Action**: Explicitly configure the RDS cluster to use the customer-managed KMS key.

**Implementation Steps**:

1. **Reference the KMS key in RDS configuration**: Update `aws_rds_cluster.prod` to include:
   ```hcl
   kms_key_id = aws_kms_key.rds.arn
   ```

2. **Verify KMS key policy**: Ensure the key policy grants the RDS service role permissions to use the key. Add a policy statement if missing:
   ```json
   {
     "Sid": "AllowRDSEncryption",
     "Effect": "Allow",
     "Principal": {
       "Service": "rds.amazonaws.com"
     },
     "Action": [
       "kms:Decrypt",
       "kms:GenerateDataKey",
       "kms:CreateGrant"
     ],
     "Resource": "*"
   }
   ```

3. **Enable CloudTrail logging** for KMS key usage to audit all encryption operations.

4. **Document key rotation requirements**: Verify that `enable_key_rotation = true` is set on `aws_kms_key.rds` (cost notes indicate this is already planned). AWS will rotate the key material annually.

**Validation**: After deployment, query the RDS cluster in AWS Console and confirm the **DB Encryption** section shows the custom KMS key ARN, not "aws/rds" (AWS-managed key).

### 3. ⚠️ MEDIUM — Enable IAM Database Authentication

**Action**: Configure the RDS cluster to accept IAM authentication tokens.

**Implementation Steps**:

1. **Update RDS configuration**:
   ```hcl
   iam_database_authentication_enabled = true
   ```

2. **Create an IAM policy** for applications to generate temporary database authentication tokens:
   ```json
   {
     "Version": "2012-10-17",
     "Statement": [
       {
         "Effect": "Allow",
         "Action": "rds-db:connect",
         "Resource": "arn:aws:rds-db:REGION:ACCOUNT:dbuser:RESOURCE-ID/*"
       }
     ]
   }
   ```

3. **Attach this policy** to the IAM roles used by EC2 instances, Lambda functions, and other compute services that connect to the database.

4. **Update application connection strings** to use IAM authentication:
   - For MySQL: Use the AWS RDS authentication plugin and generate a temporary token via AWS SDK.
   - For applications using standard JDBC/ODBC drivers: Transition gradually to token-based authentication.

5. **Document the migration path**: Maintain legacy password-based access during transition if immediate cutover is not feasible. Set a deadline for full transition.

**Benefit**: Temporary credentials (15-minute TTL), audit trail per principal, no shared passwords across environments.
