### Missing Resource Boundaries

❌ **CRITICAL**: No resource restrictions present  
   - **Policy**: Production policy with wildcard resources  
   - **Affected Resources**: All AWS resources without exception, including:
     - KMS encryption keys (enable credential compromise)
     - RDS databases (enable data theft and destruction)
     - IAM roles and policies (enable privilege escalation)
     - Security groups and network ACLs (enable lateral movement)
     - Lambda functions, S3 buckets, and VPC infrastructure (complete infrastructure access)
   - **Impact**: Attacker with this policy can access, modify, or destroy any infrastructure component; no containment possible  
   - **Remediation**: Add explicit `Resource` array specifying only required resources (e.g., `arn:aws:ec2:us-east-1:ACCOUNT:instance/i-*` for EC2-specific access)

### Missing MFA/Conditions

❌ **CRITICAL**: Destructive actions permitted without MFA authentication  
   - **Affected Principal**: Unknown principal using this policy  
   - **Missing Protections**:
     - No MFA requirement for sensitive actions (DeleteUser, DeleteRole, TerminateInstances, DeleteDatabase, etc.)
     - No IP address restrictions (access allowed from any source)
     - No time-based access constraints
     - No source VPC endpoint restrictions
     - No tag-based conditions
   - **Impact**: Credentials compromised at any time can immediately trigger infrastructure destruction; no verification step prevents accidental or malicious damage  
   - **Remediation**: Add `Condition` block requiring MFA for all destructive actions:
     ```json
     "Condition": {
       "Bool": {"aws:MultiFactorAuthPresent": "true"}
     }
     ```
     Additionally, restrict by IP (e.g., corporate network ranges only) and require VPC endpoint access for sensitive resources.

### Missing Session/Access Boundaries

❌ **CRITICAL**: Policy lacks all access boundaries and audit constraints  
   - **Policy**: Production policy with no condition keys  
   - **Missing Boundary Mechanisms**:
     - No session duration limits or token TTL enforcement
     - No IP allowlist/blocklist restrictions
     - No source tag requirements
     - No VPC endpoint enforcement
     - No service control policy (SCP) restrictions at organization level
     - No audit trail constraints or logging requirements
   - **Impact**: No method to correlate destructive actions to specific users, times, or locations; impossible to implement incident response or forensics  
   - **Remediation**: 
     1. Implement IP-based conditions: `"IpAddress": {"aws:SourceIp": ["10.0.0.0/8"]}`
     2. Add time-based restrictions: `"DateGreaterThan": {"aws:CurrentTime": "2026-01-01T00:00:00Z"}`
     3. Enable CloudTrail logging on all affected resources
     4. Attach organization-level SCPs to deny wildcard actions
     5. Require session tags for audit correlation: `"StringEquals": {"aws:PrincipalOrgID": "o-XXXXXXXXXX"}`
