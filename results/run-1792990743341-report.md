- **aws_s3_bucket.logs** (MEDIUM): No Object Lock or retention configuration is set, so audit logs can be modified or deleted before any compliance retention period ends.

- Multi-region CloudTrail with management events is low cost, but S3 storage and PUT request charges will grow with log volume and the self-logging configuration adds extra requests.

**Proposed remediation (MFA delete):**

The pipeline produced two candidate fixes. The first (out-of-band enablement with `ignore_changes`) is the more reliable pattern:

1. Enable MFA delete out-of-band as root:
   `aws s3api put-bucket-versioning --bucket <logs-bucket> --versioning-configuration Status=Enabled,MFADelete=Enabled --mfa "<root-mfa-arn> <code>"`
2. Set `mfa_delete = "Enabled"` in HCL and add `lifecycle { ignore_changes = [mfa_delete] }` so Terraform does not attempt the change.
3. Add a bucket policy Deny on `s3:DeleteObjectVersion` where `aws:MultiFactorAuthPresent` is `"false"`.

The second candidate passes an MFA value through a Terraform variable (`mfa = var.root_mfa_serial_and_code`). It is less preferable because it places a root MFA credential in a Terraform run, and the one-line HCL block is hard to review. It also omits the bucket-policy Deny. If it is used, the variable must be marked `sensitive`, applied only with root credentials, and paired with an SCP or bucket-policy Deny on `s3:DeleteObjectVersion` and `s3:PutLifecycleConfiguration` for non-break-glass roles.

**Findings without a proposed remediation:** the KMS key policy, CloudTrail `kms_key_id`, TLS-enforcement deny, `Bool` condition correction, KMS deletion window, Object Lock, and self-logging loop. These are addressed in the recommendations below.

### Cost Impact

- **Noncurrent version accumulation:** Versioning is enabled on `aws_s3_bucket.logs` with no lifecycle rule, so noncurrent audit-log versions will accumulate storage costs indefinitely.
- **KMS fees:** `aws_kms_key.logs` carries a fixed monthly key fee. `bucket_key_enabled = true` reduces per-request KMS charges on S3 writes, so keep it enabled when adding the CloudTrail grant.
- **Log volume and self-logging:** S3 storage and PUT request charges will grow with log volume. The self-logging configuration on `aws_s3_bucket_logging.logs` adds extra requests and storage with no compliance benefit.
