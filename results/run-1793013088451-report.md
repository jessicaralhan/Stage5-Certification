## Unified Recommendations

### Priority 1: CRITICAL – Immediate Action Required

**1. Halt Deployment and Revoke Active Policy**
- Do not deploy this policy to any environment (dev, staging, production)
- If this policy is currently active, revoke it immediately and replace with a compliant policy
- Audit all principals that may have used this policy in the past 30 days
- Review CloudTrail logs for unauthorized actions performed under this policy's permissions

**2. Redesign Policy for Least Privilege**
- Identify the specific workload or application this policy is intended to serve
- Document required actions (e.g., if this is for an EC2 instance: `ec2:DescribeInstances`, `autoscaling:SetDesiredCapacity`, `cloudwatch:PutMetricAlarm`)
- Specify target resources using ARNs (example: `arn:aws:ec2:us-east-1:ACCOUNT:instance/i-*` for compute-only access)
- Create a dedicated IAM role with a descriptive name reflecting its purpose (e.g., `AutoScalingManagerRole`, `DataProcessingRole`)
- Assign this role only to the specific service, application, or infrastructure component that requires it

**3. Enforce MFA for Destructive Operations**
- Add condition block to the policy:
  ```json
  "Condition": {
    "Bool": {
      "aws:MultiFactorAuthPresent": "true"
    }
  }
  ```
- Apply this condition specifically to high-impact actions:
  - All `iam:*` actions
  - `ec2:Terminate*`, `ec2:StopInstances`, `ec2:ModifyInstanceAttribute`
  - `rds:Delete*`, `rds:ModifyDBInstance`
  - `kms:ScheduleKeyDeletion`, `kms:DisableKey`
  - `s3:DeleteBucket`, `s3:DeleteObject`
  - `dynamodb:DeleteTable`

**4. Implement Conditional Access Controls**
- Add IP-based restrictions for production access:
  ```json
  "Condition": {
    "IpAddress": {
      "aws:SourceIp": ["10.0.0.0/8", "203.0.113.0/24"]
    }
  }
  ```
- Add environment tag restrictions:
  ```json
  "Condition": {
    "StringEquals": {
      "aws:RequestedRegion": "us-east-1",
      "aws:PrincipalTag/Environment": "production"
    }
  }
  ```
- Add session duration limits for temporary credentials (use `aws:SessionDuration`)

### Priority 2: HIGH – Required Before Production Deployment

**5. Establish Role-Based Access Control (RBAC) Structure**
- Create role hierarchy: Application Role → Service Role → Resource-Specific Role
- Example: `DataPipelineExecutionRole` (allows describe/invoke) → `DataPipelineExecution-RDSAccess` (allows read from specific RDS instance)
- Document each role's purpose, permissions, and authorized principals

**6. Implement Resource Tagging Strategy**
- Tag all production resources with: `Environment: production`, `CostCenter: X`, `Owner: TeamName`, `Criticality: High|Medium|Low`
- Use these tags in IAM condition keys to limit scope dynamically
- Example condition: Only allow actions on resources tagged `Criticality: High` with MFA present

**7. Enable CloudTrail and Set Up Alerting**
- Ensure CloudTrail is capturing all IAM actions and API calls
- Configure CloudWatch alarms for:
  - Destructive actions (DeleteBucket, TerminateInstances, DeleteDBInstance)
  - Actions from unexpected IP ranges
  - Failed MFA attempts on sensitive operations
  - Principal assumption of high-privilege roles
